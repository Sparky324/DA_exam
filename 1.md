# Вопрос 1. Теорема об оценке времени работы сортировок, использующих сравнение элементов (с доказательством)

---

## 1. Формулировка теоремы

> **Теорема.** Любой алгоритм сортировки, основанный исключительно на попарном сравнении элементов, в худшем случае выполняет не менее $\Omega(n \log n)$ сравнений для массива из $n$ элементов.

Это означает, что такие алгоритмы, как сортировка слиянием (Merge Sort), пирамидальная сортировка (Heap Sort) и быстрая сортировка (Quick Sort в среднем), являются **асимптотически оптимальными** среди сортировок сравнением — быстрее чем за $O(n \log n)$ отсортировать произвольный массив только сравнениями невозможно.

---

## 2. Модель дерева решений (Decision Tree)

Для доказательства используется модель **дерева решений**:

- Каждый **внутренний узел** дерева представляет собой одно сравнение двух элементов: $a_i \leq a_j$.
- Из каждого внутреннего узла выходят **два ребра**: левое (результат «да», т.е. $a_i \leq a_j$) и правое (результат «нет», т.е. $a_i > a_j$).
- Каждый **лист** дерева представляет собой один конкретный результат сортировки — одну перестановку исходного массива.
- Любой путь от корня до листа описывает последовательность сравнений, которую алгоритм выполнит для конкретного входного массива.
- **Высота дерева** $h$ — это максимальная длина пути от корня до листа, то есть **максимальное число сравнений** в худшем случае.

### Ключевые свойства:

1. Для массива из $n$ различных элементов существует ровно $n!$ возможных перестановок.
2. Поскольку алгоритм должен уметь выдать любую из этих перестановок, дерево решений должно содержать **не менее $n!$ листьев**.
3. Бинарное дерево высоты $h$ содержит **не более $2^h$ листьев**.

---

## 3. Доказательство

**Шаг 1.** Пусть $L$ — количество листьев в дереве решений. Тогда:
$$L \geq n!$$

**Шаг 2.** Бинарное дерево высоты $h$ имеет не более $2^h$ листьев:
$$L \leq 2^h$$

**Шаг 3.** Объединяем неравенства:
$$2^h \geq n!$$

**Шаг 4.** Логарифмируем обе части по основанию 2:
$$h \geq \log_2(n!)$$

**Шаг 5.** Оцениваем $\log_2(n!)$ снизу. Используем тот факт, что:
$$n! = 1 \cdot 2 \cdot 3 \cdots n \geq \left(\frac{n}{2}\right)^{n/2}$$

(Мы оставили только вторую половину множителей, каждый из которых $\geq n/2$, их ровно $n/2$ штук.)

Тогда:
$$\log_2(n!) \geq \log_2\left(\left(\frac{n}{2}\right)^{n/2}\right) = \frac{n}{2} \cdot \log_2\left(\frac{n}{2}\right) = \frac{n}{2}(\log_2 n - 1)$$

Следовательно:
$$h \geq \frac{n}{2}(\log_2 n - 1) = \Omega(n \log n)$$

Более точная оценка получается через **формулу Стирлинга**:
$$n! \approx \sqrt{2\pi n} \left(\frac{n}{e}\right)^n$$
$$\log_2(n!) = n \log_2 n - n \log_2 e + O(\log n) = \Theta(n \log n)$$

**Вывод:** высота любого дерева решений для сортировки $n$ элементов равна $\Omega(n \log n)$, а значит, любой алгоритм сортировки сравнением делает хотя бы $\Omega(n \log n)$ сравнений в худшем случае. $\blacksquare$

---

## 4. Следствия

| Алгоритм | Сложность (худший случай) | Достигает нижней границы? |
|---|---|---|
| Merge Sort | $O(n \log n)$ | ✅ Да |
| Heap Sort | $O(n \log n)$ | ✅ Да |
| Quick Sort | $O(n^2)$ | ❌ Нет (но в среднем $O(n \log n)$) |
| Insertion Sort | $O(n^2)$ | ❌ Нет |

> **Важно:** эта нижняя граница **не применима** к сортировкам, не использующим сравнения (Counting Sort, Radix Sort, Bucket Sort), которые при определённых условиях работают за $O(n)$. Это вопросы 2–4 вашей программы.

## 5. Код на C++: иллюстрация идеи дерева решений

Ниже приведена программа, которая строит все возможные перестановки (листья дерева решений) и демонстрирует, что их количество равно $n!$, а также рекурсивно моделирует дерево сравнений:

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cmath>

// Подсчёт факториала (количество листьев дерева решений)
long long factorial(int n) {
    long long result = 1;
    for (int i = 2; i <= n; ++i)
        result *= i;
    return result;
}

// Рекурсивная генерация всех перестановок (моделирование листьев дерева решений)
void generatePermutations(std::vector<int>& arr, int index, long long& leafCount) {
    if (index == (int)arr.size()) {
        leafCount++;
        return;
    }
    for (int i = index; i < (int)arr.size(); ++i) {
        std::swap(arr[index], arr[i]);
        generatePermutations(arr, index + 1, leafCount);
        std::swap(arr[index], arr[i]); // backtrack
    }
}

// Имитация сортировки через дерево решений: 
// перебор всех путей (для демонстрации экспоненциального роста)
int decisionTreeSortSimulation(const std::vector<int>& arr, int left, int right, int& comparisons) {
    if (left >= right) return 0;
    
    // В реальном алгоритме здесь было бы одно сравнение и ветвление.
    // Мы просто считаем, что каждое сравнение — узел дерева.
    comparisons++;
    
    // Моделируем два исхода сравнения arr[left] vs arr[right]
    if (arr[left] <= arr[right]) {
        return 1; // "левая" ветвь
    } else {
        return -1; // "правая" ветвь
    }
}

int main() {
    int n = 8;
    
    // 1. Демонстрация количества листьев
    long long leaves = factorial(n);
    std::cout << "n = " << n << std::endl;
    std::cout << "n! = " << leaves << " (минимальное число листьев)" << std::endl;
    
    // 2. Нижняя граница высоты дерева
    double minHeight = std::log2((double)leaves);
    std::cout << "log2(n!) = " << minHeight << std::endl;
    std::cout << "Минимальная высота дерева (худший случай): ceil(log2(n!)) = " 
              << (int)std::ceil(minHeight) << std::endl;
    
    // 3. Сравнение с n*log2(n)
    double nlogn = n * std::log2((double)n);
    std::cout << "n * log2(n) = " << nlogn << std::endl;
    
    // 4. Генерация всех перестановок для маленького n
    int smallN = 4;
    std::vector<int> arr(smallN);
    for (int i = 0; i < smallN; ++i) arr[i] = i + 1;
    
    long long leafCount = 0;
    generatePermutations(arr, 0, leafCount);
    std::cout << "\nДля n=" << smallN << " сгенерировано " << leafCount 
              << " перестановок (листьев дерева решений)." << std::endl;
    std::cout << "Минимальная высота дерева: " << (int)std::ceil(std::log2((double)leafCount)) 
              << std::endl;
    
    return 0;
}
```

### Вывод программы:
```
n = 8
n! = 40320 (минимальное число листьев)
log2(n!) = 15.2992
Минимальная высота дерева (худший случай): ceil(log2(n!)) = 16
n * log2(n) = 24

Для n=4 сгенерировано 24 перестановок (листьев дерева решений).
Минимальная высота дерева: 5
```

Действительно, для $n=4$: $\lceil \log_2(24) \rceil = 5$ сравнений в худшем случае необходимо.

## 6. Резюме для экзамена

1. Любая сортировка сравнением моделируется **бинарным деревом решений**.
2. Дерево должно иметь $\geq n!$ листьев (по одному на каждую перестановку).
3. Бинарное дерево высоты $h$ имеет $\leq 2^h$ листьев.
4. Следовательно, $2^h \geq n! \Rightarrow h \geq \log_2(n!) = \Omega(n \log n)$.
5. Алгоритмы Merge Sort и Heap Sort достигают этой границы и являются оптимальными.
