# Вопрос 12. 2-3-4 деревья. Основные операции. Связь с красно-чёрными деревьями

---

## 1. Определение и структура

**2-3-4 дерево** — это сбалансированное дерево поиска, являющееся частным случаем B-дерева порядка 4. В отличие от бинарных деревьев, каждый узел может содержать **от 1 до 3 ключей** и иметь **от 2 до 4 потомков**.

### Типы узлов:
-   **2-узел:** 1 ключ, 2 потомка (как в обычном BST).
    ```
      [K]
     /   \
    L     R
    ```
-   **3-узел:** 2 ключа, 3 потомка.
    ```
      [K1 | K2]
     /   |    \
    L    M     R
    ```
-   **4-узел:** 3 ключа, 4 потомка.
    ```
      [K1 | K2 | K3]
     /   |   |    \
    A    B   C     D
    ```

### Инварианты:
1.  Все листья находятся на **одинаковой глубине** (дерево идеально сбалансировано по высоте).
2.  Ключи внутри узла упорядочены: $K_1 < K_2 < K_3$.
3.  Для 3-узла $[K_1 | K_2]$: все ключи в левом поддереве $< K_1$, в среднем — между $K_1$ и $K_2$, в правом — $> K_2$. Аналогично для 4-узлов.
4.  Высота дерева с $n$ ключами: $\log_4(n+1) \leq h \leq \log_2(n+1)$, то есть $h = O(\log n)$.

---

## 2. Основные операции

### 2.1. Поиск (Search)

Аналогичен поиску в BST, но в каждом узле нужно сравнить искомый ключ с несколькими ключами узла, чтобы выбрать правильное поддерево.

**Алгоритм:**
1.  Начать с корня.
2.  Если ключ найден в текущем узле — вернуть успех.
3.  Иначе определить интервал, куда попадает ключ, и перейти в соответствующего потомка.
4.  Если дошли до листа и не нашли — ключ отсутствует.

```cpp
struct Node234 {
    int keys[3];       // До 3 ключей
    Node234* children[4]; // До 4 потомков
    int numKeys;       // Текущее количество ключей (1, 2 или 3)
    bool isLeaf;

    Node234() : numKeys(0), isLeaf(true) {
        for (int i = 0; i < 4; ++i) children[i] = nullptr;
    }
};

bool search(Node234* node, int key) {
    if (!node) return false;

    // Линейный поиск внутри узла (ключей всего 1-3)
    int i = 0;
    while (i < node->numKeys && key > node->keys[i]) {
        ++i;
    }

    // Нашли ключ в этом узле?
    if (i < node->numKeys && key == node->keys[i]) return true;

    // Если лист — ключа нет
    if (node->isLeaf) return false;

    // Спускаемся в нужное поддерево
    return search(node->children[i], key);
}
```
**Сложность:** $O(h) = O(\log n)$. Внутри каждого узла работа константная ($\leq 3$ сравнения).

### 2.2. Вставка (Insert)

Вставка всегда происходит в **лист**. Главная проблема: если мы приходим в **4-узел**, он переполнен и не может принять новый ключ.

#### Стратегия: превентивное разбиение (split on the way down)
При спуске к листу, если встречаем 4-узел, **немедленно разбиваем его** на два 2-узла, а средний ключ поднимаем в родительский узел. Это гарантирует, что родитель никогда не окажется 4-узлом (иначе он был бы разбит ранее), поэтому подъём ключа безопасен.

**Разбиение 4-узла:**
```
До:         [A | B | C]
           / |  |   \

После:          [B]
               /   \
            [A]     [C]
```

Если разбивается корень, высота дерева увеличивается на 1.

```cpp
// Разбиение 4-узла child, который является i-м потомком parent
void splitChild(Node234* parent, int i, Node234* child) {
    // Создаём правую часть из ключей [2] и детей [2],[3]
    Node234* rightPart = new Node234();
    rightPart->numKeys = 1;
    rightPart->keys[0] = child->keys[2];
    rightPart->isLeaf = child->isLeaf;

    if (!child->isLeaf) {
        rightPart->children[0] = child->children[2];
        rightPart->children[1] = child->children[3];
    }

    // Средний ключ поднимается в parent
    int midKey = child->keys[1];

    // Левая часть остаётся в child (только ключ [0] и дети [0],[1])
    child->numKeys = 1;

    // Сдвигаем ключи и потомки parent вправо, чтобы освободить место
    for (int j = parent->numKeys - 1; j >= i; --j) {
        parent->keys[j + 1] = parent->keys[j];
        parent->children[j + 2] = parent->children[j + 1];
    }
    parent->keys[i] = midKey;
    parent->children[i + 1] = rightPart;
    parent->numKeys++;
}

void insert(Node234*& root, int key) {
    // Если корень — 4-узел, разбиваем его (увеличиваем высоту)
    if (root->numKeys == 3) {
        Node234* newRoot = new Node234();
        newRoot->isLeaf = false;
        newRoot->children[0] = root;
        splitChild(newRoot, 0, root);
        root = newRoot;
    }

    // Спуск вниз с превентивным разбиением
    Node234* curr = root;
    while (true) {
        // Находим позицию
        int i = 0;
        while (i < curr->numKeys && key > curr->keys[i]) ++i;

        // Ключ уже есть?
        if (i < curr->numKeys && key == curr->keys[i]) return;

        // Лист — вставляем сюда
        if (curr->isLeaf) {
            // Сдвиг ключей вправо
            for (int j = curr->numKeys - 1; j >= i; --j)
                curr->keys[j + 1] = curr->keys[j];
            curr->keys[i] = key;
            curr->numKeys++;
            return;
        }

        // Превентивное разбиение 4-узла-потомка
        if (curr->children[i]->numKeys == 3) {
            splitChild(curr, i, curr->children[i]);
            // После разбиения определяем, в какую половину идти
            if (key > curr->keys[i]) ++i;
        }

        curr = curr->children[i];
    }
}
```

**Сложность:** Один проход сверху вниз $O(h) = O(\log n)$. Разбиение выполняется за $O(1)$.

### 2.3. Удаление (Delete)

Удаление сложнее вставки. Проблема: при удалении из 2-узла он становится пустым (1-узел недопустим).

#### Стратегия: превентивное слияние/заимствование на спуске
При спуске к удаляемому ключу, если встречаем 2-узел, делаем его «богаче» одним из способов:

1.  **Заимствование у брата:** Если соседний брат — 3- или 4-узел, берём у него один ключ через общего родителя.
2.  **Слияние с братом:** Если оба брата — 2-узлы, сливаем текущий узел с братом и средним ключом родителя в один 3-узел.

Это гарантирует, что при достижении цели удаления мы всегда окажемся в узле с $\geq 2$ ключами, и простое удаление не нарушит инвариант.

*(Код удаления очень объёмный; на экзамене достаточно описать стратегию превентивного слияния/заимствования.)*

**Сложность:** $O(h) = O(\log n)$.

## 3. Связь с красно-чёрными деревьями

Это важнейшая теоретическая часть вопроса. **2-3-4 деревья и красно-чёрные деревья изоморфны.** RB-дерево — это бинарное представление 2-3-4 дерева.

### Правила соответствия:

| 2-3-4 дерево | Красно-чёрное дерево |
| :--- | :--- |
| **4-узел** $[A \| B \| C]$ | Чёрный узел $B$ с двумя **красными** детьми $A$ и $C$ |
| **3-узел** $[A \| B]$ | Чёрный узел + один красный ребёнок (левый или правый) |
| **2-узел** $[A]$ | Просто чёрный узел без красных детей |

### Визуализация соответствия:

```
2-3-4:     [10 | 20 | 30]          RB:       20(B)
          /    |      \                     /     \
         ...   ...    ...                 10(R)   30(R)

2-3-4:     [10 | 20]               RB:      20(B)       или     10(B)
          /    |    \                      /                       \
         ...  ...   ...                  10(R)                     20(R)

2-3-4:       [15]                    RB:      15(B)
            /     \                          /     \
          ...     ...                      ...     ...
```

### Соответствие операций:

| Операция в 2-3-4 | Эквивалент в RB-дереве |
| :--- | :--- |
| Разбиение 4-узла | Перекраска + поворот (rotation) |
| Заимствование у брата | Поворот вокруг родителя |
| Слияние с братом | Перекраска родителя и братьев |
| Спуск по дереву | Обычный спуск по BST |

### Зачем это нужно?
-   **2-3-4 дерево** проще для понимания концепции сбалансированных сильноветвящихся деревьев.
-   **RB-дерево** эффективнее на практике (бинарная структура, меньше памяти на указатели, лучше кэш-локальность).
-   Доказательство корректности RB-деревьев часто проводится через доказательство свойств 2-3-4 деревьев.
-   Понимание связи помогает реализовать B-деревья и их варианты.

> **На экзамене обязательно:** Нарисовать соответствие 4-узла, 3-узла и 2-узла их RB-эквивалентам. Это основной визуальный элемент ответа.

## 4. Оценка сложности

| Операция | Время | Примечание |
| :--- | :--- | :--- |
| **Поиск** | $O(\log n)$ | Высота $\leq \log_2(n+1)$ |
| **Вставка** | $O(\log n)$ | Один проход + $O(1)$ разбиений |
| **Удаление** | $O(\log n)$ | Один проход + $O(1)$ слияний/заимствований |
| **Память** | $O(n)$ | Каждый ключ хранится ровно один раз |
| **Высота** | $\log_4(n+1) \leq h \leq \log_2(n+1)$ | Минимальная высота при всех 4-узлах, максимальная при всех 2-узлах |

Константа в $O(\log n)$ для 2-3-4 деревьев **меньше**, чем для AVL/RB, так как основание логарифма больше (до 4 вместо 2). Однако на практике бинарные деревья выигрывают за счёт меньших накладных расходов на узел.

---

## 5. Резюме для экзамена

1.  **2-3-4 дерево** — сбалансированное дерево, где узлы содержат 1–3 ключа и 2–4 потомка. Все листья на одной глубине.
2.  **Вставка:** Спуск сверху вниз с **превентивным разбиением** 4-узлов. Разбиение создаёт два 2-узла и поднимает средний ключ.
3.  **Удаление:** Спуск с **превентивным заимствованием/слиянием**, чтобы избежать пустых узлов.
4.  **Связь с RB:** 4-узел ↔ чёрный + 2 красных; 3-узел ↔ чёрный + 1 красный; 2-узел ↔ чёрный. Операции разбиения/слияния соответствуют поворотам и перекраскам.
5.  **Сложность:** Все операции $O(\log n)$. Высота в 2 раза меньше, чем у бинарных деревьев, но накладные расходы на узел выше.
