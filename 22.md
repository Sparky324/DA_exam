# Вопрос 22. Приложения суффиксного дерева: поиск подстроки, поиск набора подстрок, поиск в базе образцов, поиск наибольшей общей подстроки, статистика совпадений

---

## 1. Введение

Суффиксное дерево (ST) для строки $S$ длины $n$ строится за $O(n)$ (алгоритм Укконена, вопрос 21). После построения оно становится универсальным индексом, позволяющим решать множество задач на строках за время, зависящее только от размера запроса, а не от длины текста.

Ниже приведены основные приложения с алгоритмами и оценками сложности.

---

## 2. Поиск подстроки в строке

### Задача
Дан текст $T$ (по которому построено ST) и образец $P$ длины $m$. Найти все вхождения $P$ в $T$.

### Алгоритм
1.  Спускаемся от корня по рёбрам ST, сравнивая символы $P$ с метками рёбер.
2.  Если удалось пройти весь образец $P$ и остановиться в узле $v$ (или внутри ребра), то **все листья** в поддереве узла $v$ соответствуют началам вхождений $P$.
3.  Собираем индексы суффиксов из всех листьев поддерева $v$.

### Сложность
-   Спуск по дереву: $O(m)$ (сравнение каждого символа $P$ происходит один раз).
-   Сбор ответов: $O(k)$, где $k$ — число вхождений.
-   **Итого: $O(m + k)$**.

> Это асимптотически оптимально: нужно хотя бы прочитать образец и вывести все вхождения.

```cpp
// Псевдокод поиска
Node* findPatternNode(const string& P) {
    Node* v = root;
    int pos = 0;
    while (pos < P.size() && v != nullptr) {
        char c = P[pos];
        if (!v->children.count(c)) return nullptr;
        Node* child = v->children[c];
        int len = edgeLength(child);
        // Сравниваем P[pos..] с меткой ребра
        int match = 0;
        while (match < len && pos + match < P.size() && 
               S[child->start + match] == P[pos + match]) 
            match++;
        if (match < len && pos + match < P.size()) return nullptr; // несовпадение
        pos += match;
        if (pos >= P.size()) return child; // нашли!
        v = child;
    }
    return (pos >= P.size()) ? v : nullptr;
}
```

## 3. Поиск набора подстрок

### Задача
Дан текст $T$ и набор образцов $\{P_1, P_2, \ldots, P_k\}$. Найти все вхождения всех образцов.

### Алгоритм
Для каждого образца $P_i$ выполняем поиск как в п.2.

### Сложность
$$O\left(\sum_{i=1}^{k} |P_i| + z\right)$$
где $z$ — общее число вхождений всех образцов.

> Альтернатива: если образцов очень много, можно построить автомат Ахо-Корасик (вопрос 19) за $O(\sum |P_i| + n + z)$. Но ST выгоднее, когда текст фиксирован, а запросы приходят онлайн.

## 4. Поиск в базе образцов (Reverse Search)

### Задача
Дана **база образцов** $\{P_1, \ldots, P_k\}$ (по которой построено обобщённое суффиксное дерево или trie). Дан запросный текст $Q$. Найти все образцы из базы, которые являются подстроками $Q$.

### Подход через обобщённое суффиксное дерево
1. Строим обобщённое ST для всех образцов базы.
2. Для каждого суффикса $Q[i..]$ спускаемся по дереву, пока путь совпадает. Все терминальные узлы на пройденном пути — это образцы, начинающиеся в позиции $i$.

### Сложность
- Построение GST базы: $O(M)$, где $M = \sum |P_i|$.
- Обработка запроса $Q$: $O(|Q| + z)$, где $z$ — число найденных пар (позиция, образец).

> Это «обратная» задача по отношению к п.2: здесь база — это паттерны, а запрос — текст.

## 5. Поиск наибольшей общей подстроки (LCS) двух и более строк

### 5.1. LCS двух строк $S_1$ и $S_2$

**Алгоритм:**
1. Строим обобщённое суффиксное дерево для $S_1\$1 S_2\$2$.
2. Каждый лист помечаем битовой маской: бит 0 = принадлежит $S_1$, бит 1 = принадлежит $S_2$.
3. Для каждого внутреннего узла вычисляем OR масок всех листьев в его поддеревье (постфиксный обход).
4. Ищем самый глубокий внутренний узел, у которого маска = `11` (присутствуют суффиксы обеих строк).
5. Глубина этого узла (сумма длин меток рёбер от корня) = длина LCS. Сама подстрока = метка пути от корня до этого узла.

**Сложность:** $O(|S_1| + |S_2|)$.

### 5.2. LCS $k$ строк

Аналогично, но маска имеет $k$ битов. Ищем самый глубокий узел с маской $(1^k - 1)$.

**Сложность:** $O(N \cdot k)$, где $N = \sum |S_i|$. Для больших $k$ можно оптимизировать через bitset или подсчёт числа установленных битов.

> **Важно:** LCS здесь — это **наибольшая общая подстрока** (substring), а не подпоследовательность (subsequence). Для подпоследовательности задача NP-трудна при $k \geq 3$.

## 6. Статистика совпадений

Суффиксное дерево позволяет эффективно вычислять различные статистики подстрок.

### 6.1. Количество различных подстрок
Каждая внутренняя вершина и каждое ребро соответствуют уникальным подстрокам. Число различных подстрок:
$$\text{distinct} = \sum_{v \in \text{internal}} (\text{len}(v) - \text{len}(\text{parent}(v)))$$
где $\text{len}(v)$ — глубина строкового пути от корня до $v$.

**Сложность:** $O(n)$ (один проход по дереву).

### 6.2. Частота каждой подстроки
Частота подстроки, соответствующей узлу $v$, равна числу листьев в поддереве $v$. Вычисляется одним постфиксным обходом за $O(n)$.

### 6.3. Самая частая подстрока заданной длины $L$
Находим все узлы с глубиной $\geq L$, среди них выбираем тот, у которого глубина $\geq L$ и число листьев максимально, а ближайший предок имеет глубину $< L$. Ответ = префикс длины $L$ пути до этого узла.

**Сложность:** $O(n)$.

### 6.4. Энтропия / Ziv-Lempel факторизация
ST используется для LZ77/LZ78 сжатия: каждый новый фрагмент — это самая длинная подстрока, уже встречавшаяся ранее. Находится спуском по ST за $O(n)$ суммарно.

## 7. Сводная таблица приложений

| Задача | Время (после построения ST) | Примечание |
| :--- | :--- | :--- |
| Поиск одной подстроки | $O(m + k)$ | $m$ = длина образца, $k$ = вхождений |
| Поиск $k$ подстрок | $O(\sum m_i + z)$ | Независимо от размера текста |
| Поиск в базе образцов | $O(|Q| + z)$ | Обратный поиск |
| LCS двух строк | $O(n_1 + n_2)$ | Через обобщённое ST |
| LCS $k$ строк | $O(N \cdot k)$ | Битовые маски в узлах |
| Число различных подстрок | $O(n)$ | Сумма длин рёбер |
| Частота подстроки | $O(n)$ препроцессинг + $O(1)$ запрос | Размер поддерева |
| Проверка «является ли P подстрокой T» | $O(|P|)$ | Просто спуск без сбора листьев |

## 8. Резюме для экзамена

1.  **Поиск подстроки:** Спуск по ST за $O(m)$, сбор листьев за $O(k)$. Итого $O(m+k)$.
2.  **Набор подстрок:** Независимый поиск каждого образца. Суммарно $O(\sum m_i + z)$.
3.  **Поиск в базе образцов:** Обобщённое ST по базе + спуск по каждому суффиксу запроса.
4.  **LCS:** Обобщённое ST + битовые маски в узлах. Самый глубокий узел с полной маской = LCS. Линейное время для двух строк.
5.  **Статистика:** Число различных подстрок, частоты, энтропия — всё за $O(n)$ одним обходом дерева.
6.  **Главная идея:** Суффиксное дерево — это **универсальный линейный индекс**, превращающий задачи на подстроки в задачи обхода дерева.

> **На экзамене обязательно:** Нарисовать обобщённое ST для двух коротких строк, показать как находятся LCS и все вхождения образца. Объяснить, почему поиск за $O(m+k)$ оптимален.
