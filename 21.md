# Вопрос 21. Алгоритм Укконена. Суффиксные связи и прыжки по счетчику. Доказательство линейности алгоритма

---

## 1. Идея алгоритма

**Алгоритм Укконена (Ukkonen's algorithm)** — это оптимальный алгоритм построения суффиксного дерева за **линейное время $O(n)$**. В отличие от наивного $O(n^2)$ подхода (вопрос 20), он строит дерево инкрементально, обрабатывая символы строки слева направо, и использует три ключевых механизма для достижения линейности:

1.  **Неявные суффиксные деревья** — промежуточная структура, где некоторые суффиксы заканчиваются внутри рёбер.
2.  **Суффиксные ссылки (suffix links)** — указатели из внутреннего узла, соответствующего строке $c\alpha$, на узел, соответствующий $\alpha$. Позволяют быстро переходить между фазами расширения.
3.  **Прыжки по счётчику (skip/count trick)** — техника быстрого спуска по дереву без посимвольного сравнения, использующая знание длины меток рёбер.

> Алгоритм работает в **онлайн-режиме**: после обработки $i$-го символа мы имеем корректное неявное суффиксное дерево для префикса $S[0..i]$.

---

## 2. Основные понятия

### 2.1. Фазы и расширения
-   **Фаза $i+1$:** Переход от неявного дерева для $S[0..i]$ к неявному дереву для $S[0..i+1]$. Состоит из нескольких **расширений**.
-   **Расширение $j$ в фазе $i+1$:** Обеспечивает наличие суффикса $S[j..i+1]$ в дереве. Расширения нумеруются от $0$ до $i+1$.

### 2.2. Три правила расширения
Для суффикса $S[j..i]$ с новым символом $c = S[i+1]$:

1.  **Правило 1 (лист):** Если путь $S[j..i]$ заканчивается в листе, просто дописываем $c$ к метке листа (увеличиваем `end`). *Лист остаётся листом навсегда.*
2.  **Правило 2 (создание):** Если путь $S[j..i]$ заканчивается в узле или внутри ребра, и из этой точки нет ребра, начинающегося с $c$, то создаём новое ребро/лист с меткой $c$. Если расщеплялось ребро — создаём новый внутренний узел и **суффиксную ссылку**.
3.  **Правило 3 (уже есть):** Если путь $S[j..i+1]$ уже присутствует в дереве, ничего не делаем. **Все последующие расширения в этой фазе тоже будут по правилу 3** → можно досрочно завершить фазу.

### 2.3. Суффиксные ссылки
Для каждого внутреннего узла $v$, представляющего строку $x\alpha$ (где $x$ — один символ, $\alpha$ — возможно пустая строка), суффиксная ссылка ведёт в узел, представляющий $\alpha$.

**Зачем:** После создания нового внутреннего узла в расширении $j$ по правилу 2, в следующем расширении $j+1$ нам нужно найти позицию для суффикса $S[j+1..i+1]$. Вместо спуска от корня мы переходим по суффиксной ссылке за $O(1)$ и продолжаем оттуда.

### 2.4. Прыжки по счётчику (Skip/Count Trick)
При переходе по суффиксной ссылке мы оказываемся в узле, представляющем $\alpha$, но нам нужно найти позицию для строки $\alpha \cdot c'$ (где $c'$ — следующий символ). Длина оставшейся части пути известна.

Вместо посимвольного сравнения:
1.  Берём длину нужной подстроки $L$.
2.  Смотрим на первое ребро из текущего узла, начинающееся с нужного символа.
3.  Если длина метки ребра $\leq L$ — перепрыгиваем через всё ребро, уменьшаем $L$ на длину метки, переходим в ребёнка.
4.  Повторяем, пока $L > 0$. Останавливаемся в нужном узле или внутри ребра.

**Это позволяет спуститься на нужную глубину за $O(\text{число пройденных рёбер})$ вместо $O(\text{длина подстроки})$.**

## 3. Структура узла и код (C++)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <map>
#include <climits>

const int MAXN = 200005;
std::string s;
int n;

struct Node {
    int start, end;         // Метка ребра: s[start..end)
    int link;               // Суффиксная ссылка (-1 если нет)
    int children[256];      // Дети по первому символу ребра
    
    Node() : start(-1), end(-1), link(-1) {
        std::fill(children, children + 256, -1);
    }
    
    int edgeLen(int curPos) const {
        return std::min(end, curPos + 1) - start;
    }
};

Node tree[MAXN];
int nodeCount = 0;
int root = 0;

// Активная точка: (activeNode, activeEdge, activeLength)
int activeNode = 0, activeEdge = 0, activeLength = 0;
int remainingSuffixCount = 0;
int leafEnd = -1; // Глобальная переменная для всех листьев

int newNode(int start, int end = INT_MAX) {
    tree[nodeCount] = Node();
    tree[nodeCount].start = start;
    tree[nodeCount].end = end;
    return nodeCount++;
}

// Прыжок по счётчику: находим позицию для активной точки
bool walkDown(int curNode, int curPos) {
    int edgeLen = tree[curNode].edgeLen(curPos);
    if (activeLength >= edgeLen) {
        activeEdge += edgeLen;
        activeLength -= edgeLen;
        activeNode = curNode;
        return true; // Продолжаем спуск
    }
    return false; // Остановились внутри ребра
}

void extend(int pos) {
    leafEnd = pos;
    remainingSuffixCount++;
    int lastNewInternal = -1;
    
    while (remainingSuffixCount > 0) {
        if (activeLength == 0) activeEdge = pos;
        
        char c = s[pos];
        int& child = tree[activeNode].children[(unsigned char)s[activeEdge]];
        
        // Правило 3: уже есть
        if (child != -1) {
            int edgeLen = tree[child].edgeLen(pos);
            if (activeLength >= edgeLen) {
                activeEdge += edgeLen;
                activeLength -= edgeLen;
                activeNode = child;
                continue; // Пересчитываем активную точку
            }
            
            // Внутри ребра: проверяем следующий символ
            if (s[tree[child].start + activeLength] == c) {
                activeLength++;
                if (lastNewInternal != -1) {
                    tree[lastNewInternal].link = activeNode;
                    lastNewInternal = -1;
                }
                break; // Правило 3: досрочный выход из фазы
            }
            
            // Правило 2: расщепление ребра
            int split = newNode(tree[child].start, tree[child].start + activeLength);
            tree[activeNode].children[(unsigned char)s[activeEdge]] = split;
            
            // Новый лист
            int leaf = newNode(pos);
            tree[split].children[(unsigned char)c] = leaf;
            
            // Старый ребёнок
            tree[child].start += activeLength;
            tree[split].children[(unsigned char)s[tree[child].start]] = child;
            
            // Суффиксная ссылка
            if (lastNewInternal != -1) {
                tree[lastNewInternal].link = split;
            }
            lastNewInternal = split;
            
            child = split; // Обновляем ссылку родителя
        } else {
            // Правило 2: создание листа напрямую
            tree[activeNode].children[(unsigned char)c] = newNode(pos);
            
            if (lastNewInternal != -1) {
                tree[lastNewInternal].link = activeNode;
                lastNewInternal = -1;
            }
        }
        
        remainingSuffixCount--;
        
        // Переход к следующему расширению
        if (activeNode == root && activeLength > 0) {
            activeLength--;
            activeEdge = pos - remainingSuffixCount + 1;
        } else if (activeNode != root) {
            activeNode = tree[activeNode].link;
        }
    }
}

void buildSuffixTree(const std::string& str) {
    s = str;
    n = s.size();
    nodeCount = 0;
    root = newNode(-1, -1);
    activeNode = root;
    activeEdge = 0;
    activeLength = 0;
    remainingSuffixCount = 0;
    
    for (int i = 0; i < n; ++i) {
        extend(i);
    }
}
```

## 4. Доказательство линейности алгоритма

> **Теорема.** Алгоритм Укконена строит суффиксное дерево строки длины $n$ за время $O(n)$.

### Доказательство

Оценим общее количество операций across все $n$ фаз.

**1. Число расширений типа «правило 3» (досрочный выход).**
Каждая фаза завершается либо правилом 3, либо исчерпанием всех суффиксов. Правило 3 выполняется $O(1)$ раз на фазу (один раз привело к break). Всего фаз $n$, значит суммарно $O(n)$ проверок правила 3.

**2. Число расширений типа «правило 2» (создание узлов).**
Каждое расширение по правилу 2 создаёт **ровно один** новый внутренний узел или лист. Общее число внутренних узлов в суффиксном дереве $\leq n$, листьев ровно $n$. Следовательно, общее число расширений по правилу 2 за весь алгоритм $\leq 2n = O(n)$.

**3. Стоимость перехода по суффиксным ссылкам + skip/count.**
Это самая тонкая часть. Определим потенциал:
$$\Phi = \text{activeLength}$$

Рассмотрим изменение $\Phi$ при каждом расширении:
-   При переходе по суффиксной ссылке: $\Phi$ уменьшается на длину одного ребра (skip/count перепрыгивает целые рёбра за $O(1)$ каждое).
-   При увеличении `activeLength` (когда совпадение продолжается): $\Phi$ увеличивается на 1. Это происходит только при правиле 3 или при успешном совпадении в начале расширения.
-   `activeLength` никогда не превышает $n$ и никогда не бывает отрицательным.

Ключевой факт: **`activeLength` увеличивается не более чем на 1 за одно расширение**, а уменьшается на величину, равную числу пройденных рёбер при skip/count. Поскольку `activeLength` начинается с 0 и не превышает $n$, суммарное увеличение за весь алгоритм $\leq n$. Следовательно, суммарное уменьшение (число пройденных рёбер) также $\leq n$.

Каждое пройденное ребро при skip/count обрабатывается за $O(1)$. Значит, суммарная стоимость всех переходов по суффиксным ссылкам с skip/count за весь алгоритм есть $O(n)$.

**4. Прочие операции.**
Создание узла, установка ссылки, обновление активной точки — всё $O(1)$ на расширение.

**Итого:**
$$T(n) = O(n)_{\text{фаза 3}} + O(n)_{\text{фаза 2}} + O(n)_{\text{skip/count}} + O(n)_{\text{прочее}} = O(n)$$

$\blacksquare$

## 5. Резюме для экзамена

| Аспект | Ответ |
| :--- | :--- |
| **Алгоритм Укконена** | Онлайн-построение суффиксного дерева за $O(n)$ |
| **Неявное дерево** | Промежуточная структура; суффиксы могут заканчиваться внутри рёбер |
| **3 правила расширения** | 1: лист (дописать), 2: создать (новый узел/ребро), 3: уже есть (break) |
| **Суффиксные ссылки** | Из узла $x\alpha$ в узел $\alpha$. Позволяют $O(1)$ переход между расширениями |
| **Skip/Count** | Быстрый спуск по дереву за $O(\text{рёбра})$ вместо $O(\text{длина})$ |
| **Доказательство линейности** | Правил 2 всего $O(n)$, правил 3 по одному на фазу, skip/count амортизированно $O(n)$ через потенциал activeLength |
| **Память** | $O(n)$ узлов, каждый хранит start, end, link, children |

> **На экзамене обязательно:** Объяснить три правила расширения, нарисовать пример суффиксных ссылок, объяснить идею skip/count (прыгаем через целые рёбра, сравнивая только длины), и провести доказательство через потенциал `activeLength`.
