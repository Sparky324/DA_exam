# Вопрос 13. B-деревья. Основные операции. Оценка алгоритмической сложности выполнения операций

---

## 1. Определение и мотивация

**B-дерево** — это сбалансированное сильноветвящееся дерево поиска, оптимизированное для систем с **блочным вводом-выводом** (файловые системы, базы данных). В отличие от бинарных деревьев (AVL, RB), где каждый узел помещается в оперативную память, узел B-дерева соответствует **блоку на диске** (странице памяти).

> **Главная идея:** Минимизировать количество обращений к диску. Поскольку доступ к диску в $10^5$–$10^6$ раз медленнее доступа к RAM, высота дерева должна быть минимальной. Это достигается за счёт большого коэффициента ветвления (сотни или тысячи потомков на узел).

### Определение B-дерева порядка $t$ ($t \geq 2$)

Каждый узел (кроме корня) удовлетворяет ограничениям:
-   **Минимум ключей:** $t - 1$
-   **Максимум ключей:** $2t - 1$
-   **Потомков:** от $t$ до $2t$ (на единицу больше, чем ключей)

Корень может иметь от $1$ до $2t-1$ ключей (если дерево не пусто).

Все листья находятся на **одинаковой глубине**.

### Параметры на практике
| Параметр | Типичное значение | Пояснение |
| :--- | :--- | :--- |
| Размер блока | 4 КБ – 64 КБ | Определяется файловой системой / СУБД |
| Порядок $t$ | 100 – 1000 | Зависит от размера ключа и блока |
| Высота при $n=10^9$ | 3 – 4 | Всего 3–4 обращения к диску! |

## 2. Структура узла (C++)

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

const int T = 3; // Минимальная степень (для примера; на практике определяется размером блока)

struct BTreeNode {
    std::vector<int> keys;             // Ключи (размер от t-1 до 2t-1)
    std::vector<BTreeNode*> children;  // Потомки (размер на 1 больше keys)
    bool isLeaf;
    int n;                             // Текущее количество ключей

    BTreeNode(bool leaf) : isLeaf(leaf), n(0) {}
};
```

> На практике ключи и указатели хранятся в массивах фиксированного размера внутри блока, а не в `std::vector`. Здесь вектор используется для простоты изложения.

## 3. Основные операции

### 3.1. Поиск (Search)

Аналогичен поиску в 2-3-4 дереве (вопрос 12), но с большим числом ключей в узле.

**Алгоритм:**
1.  Загрузить текущий узел с диска (одно обращение к I/O).
2.  Линейный или **бинарный поиск** среди ключей узла, чтобы найти нужный интервал.
3.  Если ключ найден — вернуть результат.
4.  Если узел — лист, ключ не найден.
5.  Иначе рекурсивно перейти в соответствующего потомка.

```cpp
// Возвращает пару (узел, индекс ключа) или nullptr если не найден
std::pair<BTreeNode*, int> search(BTreeNode* node, int key) {
    if (!node) return {nullptr, -1};

    // Бинарный поиск внутри узла (ключей много!)
    int lo = 0, hi = node->n - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (node->keys[mid] == key) return {node, mid};
        if (key < node->keys[mid]) hi = mid - 1;
        else lo = mid + 1;
    }

    // lo теперь указывает на позицию первого ключа > key
    if (node->isLeaf) return {nullptr, -1};

    // Спускаемся в потомка children[lo]
    return search(node->children[lo], key);
}
```

**Сложность:** $O(t \cdot \log_t n)$ сравнений в RAM, но всего $O(\log_t n)$ обращений к диску.

### 3.2. Вставка (Insert)

Как и в 2-3-4 дереве, используется стратегия **превентивного разбиения** при спуске.

**Алгоритм:**
1.  Если корень полон ($2t-1$ ключей), разбить его → новый корень, высота +1.
2.  Спускаться вниз. Перед переходом в потомка проверить: если потомок полон, **разделить его заранее**.
3.  Дойдя до листа, вставить ключ (лист гарантированно не полон благодаря превентивному разбиению).

#### Разбиение полного узла (Split)
Узел с $2t-1$ ключами делится на два узла по $t-1$ ключей, а **средний ключ** (индекс $t-1$) поднимается в родительский узел.

```
До:  [k1 k2 ... k_{t-1} | k_t | k_{t+1} ... k_{2t-1}]

После:              [k_t]  ← поднимается в parent
                   /       \
      [k1..k_{t-1}]     [k_{t+1}..k_{2t-1}]
```

```cpp
// Разделяет i-го потомка узла x (который полон: имеет 2t-1 ключей)
void splitChild(BTreeNode* x, int i) {
    BTreeNode* y = x->children[i];
    BTreeNode* z = new BTreeNode(y->isLeaf);
    z->n = T - 1;

    // Правая половина ключей уходит в z
    for (int j = 0; j < T - 1; ++j)
        z->keys.push_back(y->keys[j + T]);

    // Правая половина потомков уходит в z
    if (!y->isLeaf) {
        for (int j = 0; j < T; ++j)
            z->children.push_back(y->children[j + T]);
    }

    y->n = T - 1; // Левая половина остаётся в y

    // Средний ключ поднимается в x
    x->keys.insert(x->keys.begin() + i, y->keys[T - 1]);
    x->children.insert(x->children.begin() + i + 1, z);
    x->n++;
}

void insert(BTreeNode*& root, int key) {
    // Если корень полон — разбиваем
    if (root->n == 2 * T - 1) {
        BTreeNode* newRoot = new BTreeNode(false);
        newRoot->children.push_back(root);
        splitChild(newRoot, 0);
        root = newRoot;
    }

    // Спуск с превентивным разбиением
    BTreeNode* curr = root;
    while (true) {
        // Находим позицию
        int i = curr->n - 1;
        while (i >= 0 && key < curr->keys[i]) --i;
        i++;

        // Ключ уже есть?
        if (i < curr->n && curr->keys[i] == key) return;

        // Лист — вставляем
        if (curr->isLeaf) {
            curr->keys.insert(curr->keys.begin() + i, key);
            curr->n++;
            return;
        }

        // Превентивное разбиение полного потомка
        if (curr->children[i]->n == 2 * T - 1) {
            splitChild(curr, i);
            if (key > curr->keys[i]) i++;
        }

        curr = curr->children[i];
    }
}
```

### 3.3. Удаление (Delete)

Самая сложная операция. Аналогично 2-3-4 дереву: **превентивное обогащение** при спуске, чтобы при достижении цели узел имел $\geq t$ ключей.

Три случая при удалении ключа $k$ из узла $x$:

1.  **$k$ находится в листе:** Просто удаляем (узел гарантированно имеет $\geq t$ ключей).
2.  **$k$ во внутреннем узле:**
    -   Если левый потомок имеет $\geq t$ ключей → заменяем $k$ на **предшественника** (максимум левого поддерева) и рекурсивно удаляем предшественника.
    -   Иначе если правый потомок имеет $\geq t$ ключей → заменяем на **преемника**.
    -   Иначе сливаем оба потомка с $k$ в один узел и рекурсивно удаляем из объединённого узла.
3.  **$k$ отсутствует в текущем узле:** Определяем потомка, куда нужно спуститься. Если у него только $t-1$ ключей, обогащаем:
    -   **Заимствование:** Берём ключ у соседнего брата через родителя.
    -   **Слияние:** Если оба соседа имеют $t-1$ ключей, сливаем потомка с братом и ключом родителя.

**Сложность:** $O(\log_t n)$ обращений к диску.

## 4. Оценка алгоритмической сложности

Пусть:
-   $n$ — количество ключей,
-   $t$ — минимальная степень (порядок),
-   $h$ — высота дерева.

### Высота B-дерева

> **Теорема.** Высота B-дерева порядка $t$ с $n$ ключами удовлетворяет:
> $$h \leq \log_t\left(\frac{n+1}{2}\right)$$

**Доказательство (идея):** Корень имеет минимум 2 потомка. Каждый внутренний узел (кроме корня) имеет минимум $t$ потомков. Тогда минимальное число узлов на глубине $d$:
- Глубина 0: 1 узел (корень)
- Глубина 1: $\geq 2$ узла
- Глубина 2: $\geq 2t$ узлов
- Глубина $d$: $\geq 2 \cdot t^{d-1}$ узлов

Минимальное число ключей при высоте $h$:
$$n \geq 1 + \sum_{d=1}^{h} 2 \cdot t^{d-1} \cdot (t-1) = 2t^h - 1$$
Отсюда $t^h \leq \frac{n+1}{2}$, следовательно $h \leq \log_t\left(\frac{n+1}{2}\right)$. $\blacksquare$

### Таблица сложности

| Операция | Обращения к диску | Сравнения в RAM | Примечание |
| :--- | :--- | :--- | :--- |
| **Поиск** | $O(\log_t n)$ | $O(t \cdot \log_t n)$ или $O(\log t \cdot \log_t n)$ с бин. поиском | Основной критерий — I/O |
| **Вставка** | $O(\log_t n)$ | $O(t \cdot \log_t n)$ | Превентивное разбиение |
| **Удаление** | $O(\log_t n)$ | $O(t \cdot \log_t n)$ | Превентивное слияние/заимствование |
| **Память (диск)** | $O(n)$ | — | Каждый ключ хранится один раз |
| **Высота** | $\leq \log_t\left(\frac{n+1}{2}\right)$ | — | При $t=1000, n=10^9$: $h \leq 3$ |

### Почему B-дерево быстрее AVL/RB для больших данных?

Для $n = 10^9$:
-   AVL/RB: $h \approx 30$ → **30 обращений к диску** (неприемлемо)
-   B-дерево ($t=500$): $h \approx 3$ → **3 обращения к диску**

Разница в **10 раз**, что при стоимости disk I/O даёт колоссальный выигрыш.

---

## 5. Вариации B-деревьев

-   **B+-дерево:** Все данные хранятся **только в листьях**. Внутренние узлы содержат только разделительные ключи. Листья связаны в связный список для эффективного range-query. Стандарт для реляционных СУБД.
-   **B\*-дерево:** Узлы должны быть заполнены минимум на $2/3$ (вместо $1/2$). Достигается отложенным разбиением.
-   **B-tree с буферизацией (Buffered B-tree):** Для оптимизации массовых вставок.

---

## 6. Резюме для экзамена

1.  **B-дерево** — сильноветвящееся сбалансированное дерево, оптимизированное для блочного I/O. Узел = блок на диске. Порядок $t$: от $t-1$ до $2t-1$ ключей в узле.
2.  **Поиск:** Бинарный поиск внутри узла + спуск. $O(\log_t n)$ обращений к диску.
3.  **Вставка:** Превентивное разбиение полных узлов при спуске. Разбиение создаёт два узла по $t-1$ ключей и поднимает средний ключ.
4.  **Удаление:** Превентивное заимствование/слияние при спуске. Три случая: удаление из листа, замена на предшественника/преемника, слияние потомков.
5.  **Высота:** $h \leq \log_t\left(\frac{n+1}{2}\right)$. При $t=500$ и $n=10^9$ высота всего 3.
6.  **Главное преимущество:** Минимизация обращений к диску. Именно поэтому B/B+-деревья — основа всех современных файловых систем и СУБД.
