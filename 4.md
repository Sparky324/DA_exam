# Вопрос 4. Карманная сортировка (Bucket Sort)

---

## 1. Идея алгоритма

Карманная сортировка (Bucket Sort) — это алгоритм сортировки, который **не использует сравнения** элементов напрямую (в классическом понимании нижней границы $\Omega(n \log n)$). Он работает за линейное время $O(n)$ в среднем случае при условии, что входные данные **равномерно распределены** в некотором диапазоне (обычно на отрезке $[0, 1)$).

> В отличие от сортировки подсчётом (вопрос 2), которая требует целых чисел из небольшого диапазона, карманная сортировка отлично подходит для **вещественных чисел** (float/double).

### Принцип работы:
1. **Разбиение:** Весь диапазон значений делится на $k$ непересекающихся интервалов — **карманов** (buckets). Обычно берут $k = n$.
2. **Распределение:** Каждый элемент исходного массива помещается в соответствующий карман (по формуле `index = value * k`).
3. **Сортировка внутри карманов:** Элементы внутри каждого непустого кармана сортируются любым другим алгоритмом (чаще всего сортировкой вставками — Insertion Sort, так как карманы маленькие).
4. **Слияние:** Отсортированные карманы последовательно конкатенируются (склеиваются) в итоговый массив.

---

## 2. Вариации карманной сортировки

На экзамене важно понимать, что существует несколько подходов к реализации и обобщению этого алгоритма.

### 2.1. Классическая карманная сортировка (для вещественных чисел из $[0, 1)$)
-   **Диапазон:** Строго $[0, 1)$.
-   **Формула кармана:** `bucket_index = floor(value * n)`.
-   **Внутренняя сортировка:** Insertion Sort.
-   **Условие линейности:** Равномерное распределение входных данных.

### 2.2. Обобщённая карманная сортировка (для произвольного диапазона $[\min, \max]$)
Если числа лежат в произвольном диапазоне, их нужно сначала нормализовать.
-   **Формула кармана:** `bucket_index = floor((value - min) / (max - min) * k)`.
-   Это позволяет применять алгоритм к любым числам с плавающей точкой.

### 2.3. Целочисленная карманная сортировка (Integer Bucket Sort)
Если мы сортируем целые числа, один карман может отвечать за диапазон значений (например, карман 0 хранит числа от 0 до 9, карман 1 — от 10 до 19 и т.д.).
-   **Формула:** `bucket_index = value / bucket_range`.
-   По сути, это упрощение поразрядной сортировки (Radix Sort, вопрос 3), где мы делаем только один проход по старшему разряду, а внутри используем другую сортировку.

### 2.4. Proxmap Sort (Proximity Map Sort)
Улучшенная вариация, где вместо простого равномерного разбиения используется **функция отображения (MapKey)**, которая предсказывает, куда элемент должен попасть, основываясь на его значении. Это позволяет более равномерно распределять элементы, если их распределение заранее известно (не обязательно равномерное).

### 2.5. Flash Sort
Специализированная вариация, использующая оценку минимума и максимума для вычисления кармана. Особенность: она пытается минимизировать использование дополнительной памяти, перемещая элементы внутри исходного массива (частично in-place), хотя полная реализация всё равно требует вспомогательных структур.

### 2.6. Postman's Sort (Сортировка почтальона)
Историческая вариация, описанная Робертом Седжвиком. Моделирует процесс сортировки писем на почте: сначала письма раскладываются по городам (старший разряд/признак), затем внутри городов — по улицам, затем по домам. По сути, это нерекурсивный аналог MSD Radix Sort, но с использованием иерархических карманов.

## 3. Простой код на C++

Код написан максимально просто, как вы просили. Используем `std::vector` для карманов и стандартную `std::sort` для сортировки внутри них (на практике для маленьких карманов лучше вставка, но `std::sort` делает код короче и понятнее).

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

// Классическая карманная сортировка для чисел из диапазона [0, 1)
void bucketSort(std::vector<double>& arr) {
    int n = arr.size();
    if (n <= 1) return;

    // 1. Создаём n пустых карманов
    std::vector<std::vector<double>> buckets(n);

    // 2. Распределяем элементы по карманам
    for (int i = 0; i < n; ++i) {
        int idx = (int)(arr[i] * n); // номер кармана
        // Защита от случая, когда arr[i] == 1.0
        if (idx == n) idx = n - 1; 
        buckets[idx].push_back(arr[i]);
    }

    // 3. Сортируем каждый карман
    for (int i = 0; i < n; ++i) {
        // Внутри кармана элементов мало, сортируем встроенным методом
        std::sort(buckets[i].begin(), buckets[i].end());
    }

    // 4. Склеиваем карманы обратно в исходный массив
    int idx = 0;
    for (int i = 0; i < n; ++i) {
        for (double val : buckets[i]) {
            arr[idx++] = val;
        }
    }
}

// Обобщённая версия для любого диапазона [min_val, max_val]
void bucketSortGeneral(std::vector<double>& arr) {
    int n = arr.size();
    if (n <= 1) return;

    double min_val = *std::min_element(arr.begin(), arr.end());
    double max_val = *std::max_element(arr.begin(), arr.end());

    // Если все элементы равны
    if (min_val == max_val) return;

    std::vector<std::vector<double>> buckets(n);

    for (int i = 0; i < n; ++i) {
        // Нормализуем значение в диапазон [0, 1)
        double normalized = (arr[i] - min_val) / (max_val - min_val);
        int idx = (int)(normalized * n);
        if (idx == n) idx = n - 1;
        buckets[idx].push_back(arr[i]);
    }

    for (int i = 0; i < n; ++i) {
        std::sort(buckets[i].begin(), buckets[i].end());
    }

    int idx = 0;
    for (int i = 0; i < n; ++i) {
        for (double val : buckets[i]) {
            arr[idx++] = val;
        }
    }
}

int main() {
    // Тест классической версии [0, 1)
    std::vector<double> arr1 = {0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21, 0.12, 0.23, 0.68};
    
    std::cout << "До (классика): ";
    for (double x : arr1) std::cout << x << " ";
    std::cout << "\n";

    bucketSort(arr1);

    std::cout << "После: ";
    for (double x : arr1) std::cout << x << " ";
    std::cout << "\n\n";

    // Тест обобщённой версии
    std::vector<double> arr2 = {15.5, 2.1, 8.9, 100.0, 42.4, 15.2};
    
    std::cout << "До (обобщённая): ";
    for (double x : arr2) std::cout << x << " ";
    std::cout << "\n";

    bucketSortGeneral(arr2);

    std::cout << "После: ";
    for (double x : arr2) std::cout << x << " ";
    std::cout << "\n";

    return 0;
}
```

### Вывод программы:
```
До (классика): 0.78 0.17 0.39 0.26 0.72 0.94 0.21 0.12 0.23 0.68 
После: 0.12 0.17 0.21 0.23 0.26 0.39 0.68 0.72 0.78 0.94 

До (обобщённая): 15.5 2.1 8.9 100 42.4 15.2 
После: 2.1 8.9 15.2 15.5 42.4 100 
```

## 4. Оценка сложности (почему она линейная?)

Пусть $n$ — количество элементов, $k$ — количество карманов (обычно $k = n$).
Пусть $n_i$ — количество элементов, попавших в $i$-й карман. Очевидно, что $\sum_{i=0}^{k-1} n_i = n$.

### Шаг 1: Время на распределение
Проход по массиву и вычисление индекса кармана для каждого элемента занимает:
$$T_1 = O(n)$$

### Шаг 2: Время на сортировку внутри карманов
Если внутри кармана мы используем сортировку вставками (Insertion Sort), её сложность для $n_i$ элементов равна $O(n_i^2)$.
Общее время на сортировку всех карманов:
$$T_2 = \sum_{i=0}^{k-1} O(n_i^2)$$

### Шаг 3: Математическое ожидание (Средний случай)
Если входные данные **равномерно распределены**, то вероятность попадания элемента в любой конкретный карман равна $p = 1/k$.
Тогда $n_i$ подчиняется биномиальному распределению $B(n, 1/k)$.
Известно, что математическое ожидание квадрата размера кармана:
$$E[n_i^2] = Var(n_i) + (E[n_i])^2 = n \cdot \frac{1}{k} \left(1 - \frac{1}{k}\right) + \left(\frac{n}{k}\right)^2$$

Если мы выбрали $k = n$, то $E[n_i] = 1$.
$$E[n_i^2] = 1 \cdot \left(1 - \frac{1}{n}\right) + 1^2 \approx 2$$
То есть ожидаемый размер квадрата количества элементов в одном кармане — **константа**!

Тогда ожидаемое общее время сортировки карманов:
$$E[T_2] = \sum_{i=0}^{n-1} E[O(n_i^2)] = n \cdot O(1) = O(n)$$

### Шаг 4: Время на слияние
Склеить карманы — это просто пройтись по ним и переписать элементы:
$$T_3 = O(n)$$

### Итоговая средняя сложность:
$$T_{avg} = T_1 + T_2 + T_3 = O(n) + O(n) + O(n) = O(n)$$
**Алгоритм линеен в среднем случае при равномерном распределении.** $\blacksquare$

---

## 5. Худший случай

Что будет, если данные **не** равномерны? Например, все $n$ элементов попадут в один карман.
Тогда $n_0 = n$, а остальные $n_i = 0$.
Если внутри кармана используется сортировка вставками:
$$T_{worst} = O(n^2)$$

> Чтобы избежать катастрофы в худшем случае, внутри карманов можно использовать сортировку с гарантированным временем $O(m \log m)$ (например, Merge Sort или Heap Sort). Тогда худший случай будет $O(n \log n)$, что не хуже обычных сортировок сравнением.

## 6. Сравнение с другими линейными сортировками

| Характеристика | Counting Sort (Вопрос 2) | Radix Sort (Вопрос 3) | Bucket Sort (Вопрос 4) |
| :--- | :--- | :--- | :--- |
| **Тип данных** | Только целые числа | Целые числа, строки | Вещественные числа |
| **Ограничение** | Малый диапазон $k$ | Фиксированное число разрядов | Равномерное распределение |
| **Сложность** | $O(n + k)$ | $O(d \cdot (n + R))$ | $O(n)$ в среднем |
| **Память** | $O(n + k)$ | $O(n + R)$ | $O(n + k)$ |
| **Стабильность** | Да | Да (если LSD) | Зависит от внутренней сортировки |

## 7. Резюме для экзамена

1. **Идея:** Разбить диапазон значений на $n$ карманов, раскидать элементы, отсортировать каждый карман отдельно, слить.
2. **Вариации:** Классическая ($[0,1)$), обобщённая (произвольный диапазон), целочисленная, Postman's sort, Proxmap sort.
3. **Линейность:** Доказывается через матожидание. При равномерном распределении и $k=n$ в каждом кармане в среднем $O(1)$ элементов. Суммарное время на сортировку всех карманов (даже квадратичным алгоритмом) составит $O(n)$.
4. **Худший случай:** $O(n^2)$, если все элементы попали в один карман (и внутри используется Insertion Sort).
5. **Не использует сравнений** между элементами разных карманов, поэтому теорема из вопроса 1 не применяется.
