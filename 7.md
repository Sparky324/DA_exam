# Вопрос 7. Красно-чёрные деревья (Red-Black Trees). Основные операции. Теорема о высоте красно-чёрного дерева (с доказательством)

---

## 1. Определение и свойства

**Красно-чёрное дерево (Red-Black Tree, RB-дерево)** — это бинарное дерево поиска, в котором каждый узел имеет дополнительный атрибут — **цвет** (красный или чёрный), и выполняются следующие 5 свойств:

1. **Каждый узел окрашен в красный или чёрный цвет.**
2. **Корень всегда чёрный.**
3. **Все листья (NIL-узлы) — чёрные.** (Под листьями понимаются пустые указатели `nullptr`, которые формально считаются чёрными узлами).
4. **Если узел красный, то оба его потомка чёрные.** (Не бывает двух красных узлов подряд на любом пути от корня к листу).
5. **Для каждого узла все простые пути от него до descendant-листьев содержат одинаковое количество чёрных узлов.** Это количество называется **чёрной высотой** (black-height, $bh(x)$) узла $x$.

> Свойства 4 и 5 гарантируют, что ни один путь от корня к листу не более чем вдвое длиннее любого другого. Дерево является «приближённо сбалансированным».

### Сравнение с AVL
AVL-деревья строго сбалансированы (высота $\leq 1.44 \log n$). RB-деревья слабее сбалансированы (высота $\leq 2 \log_2(n+1)$), но требуют **меньше поворотов** при вставке/удалении (максимум 2 поворота при вставке, 3 при удалении), поэтому на практике RB-деревья используются чаще (например, `std::map` и `std::set` в C++ реализованы на них).

### Структура узла (C++)

```cpp
#include <iostream>
#include <algorithm>

enum Color { RED, BLACK };

struct Node {
    int key;
    Color color;
    Node* left;
    Node* right;
    Node* parent; // В RB-дереве указатель на родителя критически важен!

    Node(int k) : key(k), color(RED), left(nullptr), right(nullptr), parent(nullptr) {}
};
```

Вместо создания реальных NIL-узлов для каждого листа, обычно используют один глобальный статический узел `T_NIL`, который окрашен в чёрный цвет. Для простоты кода ниже мы будем использовать `nullptr` и проверять на него, но логика полностью соответствует NIL-узлам.

## 2. Повороты в RB-дереве

Повороты те же самые, что в BST и AVL (вопросы 5 и 6), но **обязательно обновляются указатели `parent`**.

```cpp
// Левый поворот вокруг x
void rotateLeft(Node*& root, Node* x) {
    Node* y = x->right;
    
    // Правый потомок x становится левым потомком y
    x->right = y->left;
    if (y->left != nullptr) {
        y->left->parent = x;
    }
    
    // Родитель y становится родителем x
    y->parent = x->parent;
    if (x->parent == nullptr) {
        root = y; // x был корнем
    } else if (x == x->parent->left) {
        x->parent->left = y;
    } else {
        x->parent->right = y;
    }
    
    // x становится левым потомком y
    y->left = x;
    x->parent = y;
}

// Правый поворот вокруг y
void rotateRight(Node*& root, Node* y) {
    Node* x = y->left;
    
    y->left = x->right;
    if (x->right != nullptr) {
        x->right->parent = y;
    }
    
    x->parent = y->parent;
    if (y->parent == nullptr) {
        root = x;
    } else if (y == y->parent->left) {
        y->parent->left = x;
    } else {
        y->parent->right = x;
    }
    
    x->right = y;
    y->parent = x;
}
```

## 3. Основные операции

### 3.1. Поиск (Search)

Поиск абсолютно идентичен обычному BST. Цвета на поиск не влияют.

```cpp
Node* search(Node* root, int key) {
    while (root != nullptr && root->key != key) {
        if (key < root->key) root = root->left;
        else root = root->right;
    }
    return root;
}
```
**Сложность:** $O(\log n)$.

---

### 3.2. Вставка (Insert)

**Алгоритм:**
1. Вставляем новый узел $z$ как в обычном BST.
2. Окрашиваем его в **красный** цвет (если окрасить в чёрный, нарушится свойство 5 — чёрная высота изменится на всех путях; красный нарушает только свойство 4 локально).
3. Если родитель нового узла чёрный — всё хорошо. Если красный — нарушение (два красных подряд). Запускаем процедуру **фиксации (fixup)**.

#### Фиксация после вставки (`insertFixup`)
Рассматриваем случай, когда родитель $P$ узла $z$ — красный. Тогда дед $G$ гарантированно чёрный. Смотрим на «дядю» $U$ (брата родителя).

**Случай 1: Дядя красный.**
Перекрашиваем $P$ и $U$ в чёрный, а $G$ в красный. Проблема поднимается на 2 уровня вверх к $G$.

**Случай 2: Дядя чёрный, $z$ — «внутренний» потомок (зигзаг).**
Например, $z$ — правый потомок левого родителя. Делаем поворот вокруг $P$, чтобы свести к случаю 3.

**Случай 3: Дядя чёрный, $z$ — «внешний» потомок (зиг-зиг).**
Делаем поворот вокруг $G$. Перекрашиваем $P$ в чёрный, $G$ в красный. Баланс восстановлен!

```cpp
void insertFixup(Node*& root, Node* z) {
    // Пока родитель существует и он красный
    while (z->parent != nullptr && z->parent->color == RED) {
        
        if (z->parent == z->parent->parent->left) {
            Node* uncle = z->parent->parent->right;
            
            // Случай 1: Дядя красный
            if (uncle != nullptr && uncle->color == RED) {
                z->parent->color = BLACK;
                uncle->color = BLACK;
                z->parent->parent->color = RED;
                z = z->parent->parent; // поднимаемся выше
            } 
            else {
                // Случай 2: z - правый потомок
                if (z == z->parent->right) {
                    z = z->parent;
                    rotateLeft(root, z);
                }
                // Случай 3: z - левый потомок
                z->parent->color = BLACK;
                z->parent->parent->color = RED;
                rotateRight(root, z->parent->parent);
            }
        } 
        else {
            // Зеркальные случаи, если родитель - правый потомок
            Node* uncle = z->parent->parent->left;
            
            if (uncle != nullptr && uncle->color == RED) {
                z->parent->color = BLACK;
                uncle->color = BLACK;
                z->parent->parent->color = RED;
                z = z->parent->parent;
            } 
            else {
                if (z == z->parent->left) {
                    z = z->parent;
                    rotateRight(root, z);
                }
                z->parent->color = BLACK;
                z->parent->parent->color = RED;
                rotateLeft(root, z->parent->parent);
            }
        }
    }
    // Корень всегда чёрный
    root->color = BLACK;
}

Node* insert(Node*& root, int key) {
    Node* z = new Node(key);
    z->color = RED;
    
    // Стандартная вставка BST
    Node* y = nullptr;
    Node* x = root;
    
    while (x != nullptr) {
        y = x;
        if (z->key < x->key) x = x->left;
        else x = x->right;
    }
    
    z->parent = y;
    if (y == nullptr) root = z;
    else if (z->key < y->key) y->left = z;
    else y->right = z;
    
    // Фиксация нарушений
    insertFixup(root, z);
    return z;
}
```
**Сложность:** Спуск $O(\log n)$ + фиксация $O(\log n)$ перекрасок, но **не более 2 поворотов**. Итого $O(\log n)$.

### 3.3. Удаление (Delete)

Удаление в RB-дереве — самая сложная операция среди базовых деревьев.

**Алгоритм:**
1. Ищем узел $z$ для удаления.
2. Как в BST: если 0 или 1 потомок — удаляем напрямую. Если 2 потомка — заменяем ключ на in-order преемника $y$ (минимум правого поддерева) и удаляем $y$.
3. Пусть $x$ — узел, который занял место удалённого.
4. **Главная проблема:** Если удалённый (или замещённый) узел был **чёрным**, нарушается свойство 5 (чёрная высота уменьшается на одном из путей). Возникает так называемый «двойной чёрный» (double black) дефект у узла $x$.
5. Запускаем `deleteFixup`.

#### Фиксация после удаления (`deleteFixup`)
Пусть $x$ — узел с «дефектом» (ему не хватает одного чёрного цвета), $w$ — его брат (sibling).

**Случай 1: Брат $w$ красный.**
Перекрашиваем $w$ в чёрный, родителя в красный, делаем поворот вокруг родителя. Теперь брат стал чёрным, переходим к случаям 2, 3 или 4.

**Случай 2: Брат $w$ чёрный, и оба его потомка чёрные.**
Перекрашиваем $w$ в красный. Дефект «поднимается» к родителю.

**Случай 3: Брат $w$ чёрный, левый потомок $w$ красный, правый чёрный.**
Перекрашиваем потомков $w$, делаем поворот вокруг $w$. Сводим к случаю 4.

**Случай 4: Брат $w$ чёрный, правый потомок $w$ красный.**
Перекрашиваем $w$ в цвет родителя, родителя в чёрный, правого потомка $w$ в чёрный. Делаем поворот вокруг родителя. Дефект устранён!

```cpp
// Вспомогательная функция замены поддеревьев
void transplant(Node*& root, Node* u, Node* v) {
    if (u->parent == nullptr) root = v;
    else if (u == u->parent->left) u->parent->left = v;
    else u->parent->right = v;
    if (v != nullptr) v->parent = u->parent;
}

void deleteFixup(Node*& root, Node* x, Node* xParent) {
    // x может быть nullptr, поэтому передаём xParent явно, 
    // либо используем NIL-узлы. Здесь упрощённая логика.
    while (x != root && (x == nullptr || x->color == BLACK)) {
        if (x == xParent->left) {
            Node* w = xParent->right; // брат
            
            // Случай 1
            if (w != nullptr && w->color == RED) {
                w->color = BLACK;
                xParent->color = RED;
                rotateLeft(root, xParent);
                w = xParent->right;
            }
            
            // Случай 2
            if ((w->left == nullptr || w->left->color == BLACK) &&
                (w->right == nullptr || w->right->color == BLACK)) {
                w->color = RED;
                x = xParent;
                xParent = x->parent;
            } 
            else {
                // Случай 3
                if (w->right == nullptr || w->right->color == BLACK) {
                    if (w->left != nullptr) w->left->color = BLACK;
                    w->color = RED;
                    rotateRight(root, w);
                    w = xParent->right;
                }
                // Случай 4
                w->color = xParent->color;
                xParent->color = BLACK;
                if (w->right != nullptr) w->right->color = BLACK;
                rotateLeft(root, xParent);
                x = root; // завершаем цикл
            }
        } 
        else {
            // Зеркальная логика для правого потомка...
            // (для краткости опущена, симметрична левой)
        }
    }
    if (x != nullptr) x->color = BLACK;
}

Node* remove(Node*& root, int key) {
    Node* z = search(root, key);
    if (z == nullptr) return nullptr;
    
    Node* y = z;
    Node* x;
    Node* xParent;
    Color yOriginalColor = y->color;
    
    if (z->left == nullptr) {
        x = z->right;
        xParent = z->parent;
        transplant(root, z, z->right);
    } else if (z->right == nullptr) {
        x = z->left;
        xParent = z->parent;
        transplant(root, z, z->left);
    } else {
        // Два потомка: ищем преемника
        y = z->right;
        while (y->left != nullptr) y = y->left;
        yOriginalColor = y->color;
        x = y->right;
        
        if (y->parent == z) {
            xParent = y;
        } else {
            xParent = y->parent;
            transplant(root, y, y->right);
            y->right = z->right;
            y->right->parent = y;
        }
        transplant(root, z, y);
        y->left = z->left;
        y->left->parent = y;
        y->color = z->color;
    }
    
    delete z;
    
    // Если удалённый узел был чёрным, нужна фиксация
    if (yOriginalColor == BLACK) {
        deleteFixup(root, x, xParent);
    }
    
    return nullptr;
}
```
**Сложность:** $O(\log n)$. Не более 3 поворотов.

## 4. Теорема о высоте красно-чёрного дерева (с доказательством)

Это центральный теоретический вопрос билета.

### Формулировка

> **Теорема.** Красно-чёрное дерево, содержащее $n$ внутренних (не NIL) узлов, имеет высоту $h$, удовлетворяющую неравенству:
> $$h \leq 2 \log_2(n + 1)$$

Это означает, что $h = O(\log n)$.

### Доказательство

Доказательство проводится в два этапа: сначала оцениваем минимальное количество узлов через чёрную высоту, затем связываем чёрную высоту с общей высотой.

**Шаг 1. Оценка числа узлов через чёрную высоту**

> **Лемма.** Поддерево с корнем $x$ содержит не менее $2^{bh(x)} - 1$ внутренних узлов, где $bh(x)$ — чёрная высота узла $x$ (количество чёрных узлов на любом пути от $x$ до листа, не считая сам $x$).

*Доказательство леммы по индукции:*

*База:* Если $bh(x) = 0$, то $x$ — это NIL-лист. Количество внутренних узлов равно $0$. Формула: $2^0 - 1 = 0$. Верно.

*Переход:* Пусть $x$ — внутренний узел с двумя потомками $L$ (левый) и $R$ (правый).
Чёрная высота потомков:
- Если потомок красный, его чёрная высота равна $bh(x)$ (сам красный узел не считается чёрным).
- Если потомок чёрный, его чёрная высота равна $bh(x) - 1$.
В любом случае, $bh(\text{потомка}) \geq bh(x) - 1$.

По предположению индукции, каждый потомок содержит не менее $2^{bh(x)-1} - 1$ внутренних узлов.
Тогда общее число узлов в поддереве $x$:
$$n(x) = 1 + n(L) + n(R)$$
$$n(x) \geq 1 + (2^{bh(x)-1} - 1) + (2^{bh(x)-1} - 1)$$
$$n(x) \geq 1 + 2 \cdot 2^{bh(x)-1} - 2$$
$$n(x) \geq 2^{bh(x)} - 1$$
Лемма доказана. $\blacksquare$

**Шаг 2. Связь чёрной высоты и общей высоты**

Рассмотрим любой путь от корня к листу длиной $h$.
Согласно **свойству 4** RB-дерева, на этом пути не может быть двух красных узлов подряд. Это значит, что **как минимум половина** узлов на любом пути — чёрные (не считая NIL-лист).

Следовательно, чёрная высота корня $bh(root)$ связана с общей высотой $h$ неравенством:
$$bh(root) \geq \frac{h}{2}$$

**Шаг 3. Объединение результатов**

Применим лемму к корню всего дерева. Общее число узлов в дереве равно $n$:
$$n \geq 2^{bh(root)} - 1$$

Подставим оценку $bh(root) \geq h/2$:
$$n \geq 2^{h/2} - 1$$

Прибавим 1 к обеим частям:
$$n + 1 \geq 2^{h/2}$$

Прологарифмируем по основанию 2:
$$\log_2(n + 1) \geq \frac{h}{2}$$

Умножим на 2:
$$h \leq 2 \log_2(n + 1)$$

**Вывод:** Высота красно-чёрного дерева из $n$ узлов не превышает $2 \log_2(n+1)$. Следовательно, $h = O(\log n)$, что гарантирует логарифмическое время работы поиска, вставки и удаления. $\blacksquare$

## 5. Сводная таблица сложности

| Операция | Худший случай | Средний случай | Примечание |
| :--- | :--- | :--- | :--- |
| **Поиск** | $O(\log n)$ | $O(\log n)$ | Как в BST |
| **Вставка** | $O(\log n)$ | $O(\log n)$ | $\leq 2$ поворота, $O(\log n)$ перекрасок |
| **Удаление** | $O(\log n)$ | $O(\log n)$ | $\leq 3$ поворота, $O(\log n)$ перекрасок |
| **Память** | $O(n)$ | $O(n)$ | +1 бит на цвет, +указатель на `parent` |
| **Высота** | $\leq 2 \log_2(n+1)$ | $\approx \log_2 n$ | Слабее AVL ($1.44 \log n$), но быстрее на модификациях |

## 6. Резюме для экзамена

1. **RB-дерево** — BST с 5 свойствами (цвета, корень чёрный, листья чёрные, нет двух красных подряд, одинаковая чёрная высота).
2. **Операции:** Поиск стандартный. Вставка: добавляем красный узел, фиксируем перекрасками и $\leq 2$ поворотами. Удаление: удаляем как в BST, если удалён чёрный — фиксируем «двойной чёрный» дефект $\leq 3$ поворотами.
3. **Теорема о высоте:** Доказывается через лемму $n \geq 2^{bh(root)} - 1$ и факт, что красных узлов не больше половины на пути ($bh \geq h/2$). Итог: $h \leq 2 \log_2(n+1)$.
4. **Преимущество перед AVL:** Меньше структурных изменений (поворотов) при вставке/удалении, что делает RB-деревья стандартом для библиотек (например, `std::map` / `std::set` в C++ STL).
