# Вопрос 14. Поиск подстроки в строке. Наивный алгоритм поиска

---

## 1. Постановка задачи

Даны:
-   **Текст** $T$ длины $n$
-   **Образец (паттерн)** $P$ длины $m$, где $m \leq n$

Требуется найти все вхождения образца $P$ в текст $T$, то есть все такие позиции $i$ ($0 \leq i \leq n - m$), что $T[i..i+m-1] = P[0..m-1]$.

---

## 2. Наивный алгоритм (Brute Force)

### Идея
Проверяем каждое возможное положение образца в тексте. Для каждой позиции сдвига $s$ от $0$ до $n-m$ посимвольно сравниваем образец с соответствующим фрагментом текста. При первом несовпадении прекращаем сравнение и переходим к следующему сдвигу.

### Псевдокод
```
NAIVE-SEARCH(T, P):
    n = length(T)
    m = length(P)
    для s от 0 до n - m:
        если T[s..s+m-1] == P[0..m-1]:
            вывести "Найдено вхождение в позиции s"
```

### Код на C++

```cpp
#include <iostream>
#include <string>
#include <vector>

// Возвращает список всех позиций вхождений
std::vector<int> naiveSearch(const std::string& text, const std::string& pattern) {
    std::vector<int> occurrences;
    int n = text.size();
    int m = pattern.size();

    if (m > n || m == 0) return occurrences;

    // Перебор всех возможных сдвигов
    for (int s = 0; s <= n - m; ++s) {
        bool match = true;
        
        // Посимвольное сравнение
        for (int j = 0; j < m; ++j) {
            if (text[s + j] != pattern[j]) {
                match = false;
                break; // Прерываем при первом несовпадении
            }
        }

        if (match) {
            occurrences.push_back(s);
        }
    }

    return occurrences;
}

int main() {
    std::string text = "ababcababcabc";
    std::string pattern = "abc";

    auto result = naiveSearch(text, pattern);

    std::cout << "Вхождения \"" << pattern << "\" в \"" << text << "\":\n";
    for (int pos : result) {
        std::cout << "  Позиция " << pos << "\n";
    }

    return 0;
}
```

### Вывод:
```
Вхождения "abc" в "ababcababcabc":
  Позиция 2
  Позиция 7
  Позиция 10
```

## 3. Оценка сложности

Пусть $n$ — длина текста, $m$ — длина образца.

### Худший случай: $O(n \cdot m)$

Худший случай возникает, когда при каждом сдвге мы выполняем почти полное сравнение ($m-1$ совпадений), а несовпадение происходит только на последнем символе.

**Пример худшего случая:**
- Текст: `aaaa...aaa` ($n$ символов 'a')
- Образец: `aaa...aab` ($m-1$ символов 'a' + один 'b')

Для каждого из $n - m + 1$ сдвигов выполняется $m$ сравнений.
$$T_{worst}(n, m) = (n - m + 1) \cdot m = O(n \cdot m)$$

При $m \approx n/2$ это даёт $\Theta(n^2)$.

### Лучший случай: $O(n)$

Если первый же символ образца не совпадает с текстом на каждом сдвиге, то на каждый сдвиг тратится $O(1)$ сравнений.
$$T_{best}(n, m) = O(n)$$

### Средний случай

При случайных текстах и образцах над алфавитом размера $|\Sigma|$ вероятность совпадения первых $k$ символов равна $1/|\Sigma|^k$. Ожидаемое число сравнений на один сдвиг:
$$E[\text{сравнений}] = \sum_{k=0}^{m-1} \frac{1}{|\Sigma|^k} < \frac{|\Sigma|}{|\Sigma| - 1} = O(1)$$

Следовательно, **средняя сложность**: $O(n)$.

### Сводная таблица

| Случай | Время | Условие |
| :--- | :--- | :--- |
| **Лучший** | $O(n)$ | Несовпадение на первом символе |
| **Средний** | $O(n)$ | Случайный текст и образец |
| **Худший** | $O(n \cdot m)$ | Повторяющиеся символы, несовпадение в конце |
| **Память** | $O(1)$ | Никаких дополнительных структур |

---

## 4. Недостатки наивного алгоритма

1.  **Квадратичная сложность в худшем случае.** Для больших текстов и паттернов это неприемлемо.
2.  **Не использует информацию о предыдущих сравнениях.** Если мы нашли частичное совпадение длиной $k$ и затем получили несовпадение, наивный алгоритм «забывает» об этом и начинает заново со следующего сдвига. Более продвинутые алгоритмы (KMP, Z-функция, Бойер-Мур) используют эту информацию для пропуска заведомо бесполезных сдвигов.
3.  **Не подходит для потоковой обработки**, так как может потребоваться возврат назад по тексту (хотя сама реализация выше читает текст последовательно, более эффективные алгоритмы гарантируют строго линейное чтение).

---

## 5. Значение для экзамена

Наивный алгоритм важен как:
-   **Базовая точка отсчёта** для понимания проблемы поиска подстроки.
-   **Контраст** для мотивации изучения линейных алгоритмов (Z-функция, KMP, Бойер-Мур, Ахо-Корасик).
-   **Практический инструмент** для очень коротких паттернов или одноразовых поисков, где накладные расходы на препроцессинг (построение таблиц) превышают выгоду от линейного алгоритма.

> **На экзамене:** Обязательно приведите пример худшего случая (`aaa...a` vs `aaa...b`) и объясните, почему именно он приводит к квадратичной сложности. Это ключевой момент ответа.

## 6. Резюме для экзамена

1.  **Задача:** Найти все вхождения строки $P$ длины $m$ в строку $T$ длины $n$.
2.  **Наивный алгоритм:** Перебор всех $n-m+1$ сдвигов, посимвольное сравнение до первого несовпадения.
3.  **Сложность:** Лучший/средний $O(n)$, худший $O(n \cdot m)$. Память $O(1)$.
4.  **Худший случай:** Текст и образец состоят из одинаковых символов, несовпадение на последнем символе каждого сдвига.
5.  **Главный недостаток:** Не использует информацию о предыдущих совпадениях, что приводит к повторным сравнениям одних и тех же символов текста.
