## 1. Префикс-функция и её связь с Z-функцией

### Определение префикс-функции
**Префикс-функция** $\pi[i]$ для строки $S$ длины $n$ — это длина наибольшего **собственного** префикса подстроки $S[0..i]$, который одновременно является её суффиксом:
$$\pi[i] = \max\{k < i+1 \mid S[0..k-1] = S[i-k+1..i]\}$$

### Связь с Z-функцией
Z-функцию $z[i]$ можно использовать для вычисления префикс-функции за $O(n)$ без классического алгоритма.

**Идея:** Если $z[j] = k > 0$, то префикс длины $k$ совпадает с подстрокой, начинающейся в позиции $j$. Значит, для позиции $i = j + k - 1$ значение $\pi[i] \geq k$. Проходим по всем $j$ и обновляем $\pi[j + z[j] - 1] = \max(\pi[j + z[j] - 1], z[j])$. Затем делаем проход слева направо, распространяя значения: $\pi[i] = \max(\pi[i], \pi[i-1])$ с учётом ограничений.

Однако на экзамене чаще требуют **классический алгоритм** построения префикс-функции, а знание связи с Z-функцией показывает глубину понимания.

## 2. Классическое построение префикс-функции за $O(n)$

### Алгоритм
Поддерживаем текущее значение $\pi[i-1]$. Для вычисления $\pi[i]$:
1. Начинаем с кандидата $j = \pi[i-1]$.
2. Пока $j > 0$ и $S[j] \neq S[i]$, уменьшаем $j = \pi[j-1]$ (переходим к следующему меньшему бордеру).
3. Если $S[j] == S[i]$, увеличиваем $j++$.
4. $\pi[i] = j$.

### Код на C++

```cpp
#include <iostream>
#include <string>
#include <vector>

std::vector<int> prefixFunction(const std::string& s) {
    int n = s.size();
    std::vector<int> pi(n, 0);
    
    for (int i = 1; i < n; ++i) {
        int j = pi[i - 1];
        
        // Откатываемся по цепочке бордеров
        while (j > 0 && s[j] != s[i]) {
            j = pi[j - 1];
        }
        
        if (s[j] == s[i]) {
            j++;
        }
        
        pi[i] = j;
    }
    
    return pi;
}

int main() {
    std::string s = "abacabab";
    auto pi = prefixFunction(s);
    
    std::cout << "S:  ";
    for (char c : s) std::cout << c << " ";
    std::cout << "\npi: ";
    for (int v : pi) std::cout << v << " ";
    std::cout << "\n";
    
    return 0;
}
```

### Вывод:
```
S:  a b a c a b a b 
pi: 0 0 1 0 1 2 3 2 
```

## 3. Классический алгоритм KMP поиска

### Идея
Строим префикс-функцию для составной строки $P\#T$ (как в Z-функции), либо используем префикс-функцию только паттерна $P$ и сканируем текст отдельно. Второй подход экономит память.

**Алгоритм поиска (без составной строки):**
1. Вычисляем $\pi$ для паттерна $P$.
2. Поддерживаем указатель $j$ — длину текущего совпадения префикса $P$ с суффиксом текста.
3. Для каждого символа текста $T[i]$:
   - Пока $j > 0$ и $P[j] \neq T[i]$, откатываем $j = \pi[j-1]$.
   - Если $P[j] == T[i]$, увеличиваем $j++$.
   - Если $j == m$, найдено вхождение в позиции $i - m + 1$. Сбрасываем $j = \pi[j-1]$ для поиска следующих вхождений.

### Код на C++

```cpp
std::vector<int> kmpSearch(const std::string& text, const std::string& pattern) {
    std::vector<int> occurrences;
    int n = text.size(), m = pattern.size();
    if (m > n || m == 0) return occurrences;
    
    std::vector<int> pi = prefixFunction(pattern);
    
    int j = 0; // Длина текущего совпадения
    for (int i = 0; i < n; ++i) {
        while (j > 0 && pattern[j] != text[i]) {
            j = pi[j - 1];
        }
        if (pattern[j] == text[i]) {
            j++;
        }
        if (j == m) {
            occurrences.push_back(i - m + 1);
            j = pi[j - 1]; // Продолжаем поиск перекрывающихся вхождений
        }
    }
    
    return occurrences;
}
```

## 4. Алгоритм реального времени (Real-Time KMP)

### Проблема классического KMP
В классическом KMP при несовпадении мы можем делать **множественные откаты** ($j = \pi[j-1]$) на одном и том же символе текста $T[i]$. Это означает, что время обработки одного символа текста не ограничено константой, хотя *амортизированное* время линейно.

Для систем реального времени (стриминг, сетевые протоколы) это недопустимо: нужна гарантия $O(1)$ на каждый символ входа.

### Решение: оптимизированная таблица переходов
Строим модифицированную таблицу $\pi'[j][c]$ или оптимизированную версию $\pi^*$, где при несовпадении сразу переходим к нужному состоянию без цикла `while`.

**Оптимизированная префикс-функция $\pi^*$:**
$$\pi^*[j] = \begin{cases} \pi[j], & \text{если } P[\pi[j]] \neq P[j] \\ \pi^*[\pi[j]], & \text{иначе} \end{cases}$$

Это устраняет «холостые» откаты: если после отката мы снова увидим тот же символ, который уже привёл к несовпадению, мы сразу откатимся дальше.

### Код построения оптимизированной таблицы

```cpp
std::vector<int> optimizedPrefixFunction(const std::string& p) {
    int m = p.size();
    std::vector<int> pi = prefixFunction(p);
    std::vector<int> piStar(m, 0);
    
    for (int j = 1; j < m; ++j) {
        if (p[pi[j]] != p[j]) {
            piStar[j] = pi[j];
        } else {
            piStar[j] = piStar[pi[j]];
        }
    }
    
    return piStar;
}
```

### Поиск в реальном времени
Заменяем `j = pi[j-1]` на `j = piStar[j-1]` в цикле `while`. Благодаря оптимизации, цикл `while` выполняется **не более 1 раза** на каждый символ текста (либо совпадение, либо один откат + совпадение/несовпадение).

**Гарантия:** Каждый символ текста обрабатывается за $O(1)$ в худшем случае. $\blacksquare$

## 5. Доказательство линейности классического KMP

> **Теорема.** Алгоритм KMP (построение префикс-функции + поиск) работает за время $O(n + m)$.

### Доказательство для построения префикс-функции

Введём потенциал: $\Phi = j$ (текущее значение переменной $j$).

На каждой итерации внешнего цикла ($i$ увеличивается на 1):
-   Операция `j++` увеличивает $\Phi$ на 1. Это происходит **не более $n$ раз** за весь алгоритм (так как $i$ растёт от 1 до $n-1$, и $j$ не может расти быстрее $i$).
-   Операция `j = pi[j-1]` **строго уменьшает** $\Phi$ (так как $\pi[k] < k+1$ для собственного бордера). Поскольку $\Phi \geq 0$, общее число уменьшений не превышает общего числа увеличений, то есть $\leq n$.

Следовательно, общее число итераций внутреннего цикла `while` за весь алгоритм $\leq n$.

**Время построения $\pi$: $O(n)$.** $\blacksquare$

### Доказательство для фазы поиска

Аналогично: переменная $j$ увеличивается на 1 не более $n$ раз (по одному на символ текста) и уменьшается не более $n$ раз. Общее число операций $O(n)$.

**Общее время KMP: $O(n + m)$.** $\blacksquare$

## 6. Построение префикс-функции через Z-функцию (дополнительно)

Хотя классический метод проще, связь с Z-функцией полезна теоретически:

```cpp
std::vector<int> piFromZ(const std::string& s) {
    int n = s.size();
    auto z = zFunction(s); // из вопроса 15
    std::vector<int> pi(n, 0);
    
    for (int i = 1; i < n; ++i) {
        if (z[i] > 0) {
            int endPos = i + z[i] - 1;
            pi[endPos] = std::max(pi[endPos], z[i]);
        }
    }
    
    // Распространяем значения: если pi[i] >= k, то pi[i-1] >= k-1
    for (int i = n - 1; i > 0; --i) {
        if (pi[i] > 0) {
            pi[i - 1] = std::max(pi[i - 1], pi[i] - 1);
        }
    }
    
    return pi;
}
```

Это также работает за $O(n)$, так как Z-функция строится за $O(n)$, а проходы линейны.

## 7. Резюме для экзамена

| Аспект | Ответ |
| :--- | :--- |
| **Префикс-функция** | $\pi[i]$ = длина наибольшего собственного бордера $S[0..i]$ |
| **Связь с Z-функцией** | $z[j]=k \Rightarrow \pi[j+k-1] \geq k$; можно построить $\pi$ за $O(n)$ через $z$ |
| **Классический KMP** | Строим $\pi(P)$, сканируем $T$ с откатами по $\pi$. Время $O(n+m)$ |
| **Доказательство линейности** | Потенциал $j$: растёт $\leq n$ раз, убывает $\leq n$ раз. Амортизация |
| **Real-Time KMP** | Оптимизированная таблица $\pi^*$ устраняет множественные откаты. Гарантия $O(1)$ на символ текста |
| **Память** | $O(m)$ для таблицы $\pi$ |

> **На экзамене обязательно:** Нарисовать пример работы префикс-функции, объяснить амортизационный анализ через потенциал $j$, и упомянуть real-time вариант как улучшение для потоковой обработки.
