## 1. Определение суффиксного дерева

**Суффиксное дерево** для строки $S$ длины $n$ — это сжатое префиксное дерево (compact trie), построенное на **всех суффиксах** строки $S$.

### Формальные свойства:
1. Дерево имеет ровно $n$ листьев, соответствующих суффиксам $S[0..], S[1..], \ldots, S[n-1..]$.
2. Каждый внутренний узел (кроме корня) имеет **не менее двух детей** (сжатие).
3. Каждое ребро помечено **непустой подстрокой** $S$.
4. Метки рёбер, выходящих из одного узла, начинаются с **разных символов**.
5. Путь от корня до листа $i$ образует строку, в точности равную суффиксу $S[i..n-1]$.

> Для однозначности построения к строке обычно добавляют уникальный терминальный символ `$`, которого нет в алфавите. Это гарантирует, что ни один суффикс не является префиксом другого, и каждому суффиксу соответствует ровно один лист.

### Пример
Для строки `banana$`:
```
         root
        / | \     \
      a   banana$  na
     / \           / \
   na   $        na   $
  / \           / \
 na   $       na   $
 / \         / \
na   $     $    (leaf 6)
|
$
```
*(Упрощённая схема; реальное дерево содержит все 7 суффиксов)*

### Размер
Несмотря на то, что суммарная длина всех суффиксов равна $O(n^2)$, суффиксное дерево занимает **$O(n)$ памяти**, так как рёбра хранят указатели на позиции в исходной строке $(start, length)$, а не копии подстрок. Число узлов $\leq 2n$.

## 2. Структура узла (C++)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <map>

struct SuffixTreeNode {
    // Дети: ключ = первый символ метки ребра
    std::map<char, SuffixTreeNode*> children;
    
    int start;          // Начало метки ребра в исходной строке
    int end;            // Конец метки (exclusive). Для листьев может быть ссылкой на n
    int suffix_index;   // Индекс суффикса (только для листьев)
    
    SuffixTreeNode* suffix_link; // Суффиксная связь (для алгоритма Укконена)
    
    SuffixTreeNode(int s, int e) 
        : start(s), end(e), suffix_index(-1), suffix_link(nullptr) {}
};
```

> На практике вместо `std::map` используют массив фиксированного размера или хеш-таблицу для $O(1)$ перехода по символу.

## 3. Неявное суффиксное дерево

### Определение
**Неявное суффиксное дерево** — это промежуточная структура, получаемая из суффиксного дерева строки $S[0..i]$ путём удаления терминального символа и схлопывания путей, которые перестали быть ветвящимися.

В неявном дереве:
- Некоторые суффиксы могут заканчиваться **внутри ребра**, а не в узле.
- Нет явных листьев для всех суффиксов.
- Корень может иметь только одного ребёнка.

### Зачем нужно?
Алгоритм Укконена (вопрос 21) строит суффиксное дерево **инкрементально**: на шаге $i$ он строит неявное суффиксное дерево для $S[0..i]$, а затем расширяет его до неявного дерева для $S[0..i+1]$. В конце добавляется `$`, превращая неявное дерево в явное.

Это позволяет избежать полного перестроения дерева на каждом шаге и достичь линейного времени.

## 4. Наивный алгоритм построения

### Алгоритм
1. Для каждого суффикса $S[i..n-1]$ ($i = 0, \ldots, n-1$):
   - Спускаемся от корня по дереву, сравнивая символы суффикса с метками рёбер.
   - Если находим расхождение внутри ребра — **расщепляем ребро** и создаём новый лист.
   - Если доходим до существующего листа — суффикс уже представлен (возможно, при наличии `$` этого не случается).
2. Повторяем для всех $n$ суффиксов.

### Код на C++ (упрощённый)

```cpp
class NaiveSuffixTree {
    std::string s;
    SuffixTreeNode* root;
    
    void insertSuffix(int suffixStart) {
        SuffixTreeNode* curr = root;
        int pos = suffixStart;
        
        while (pos < (int)s.size()) {
            char c = s[pos];
            
            if (curr->children.find(c) == curr->children.end()) {
                // Создаём новый лист
                curr->children[c] = new SuffixTreeNode(pos, s.size());
                curr->children[c]->suffix_index = suffixStart;
                return;
            }
            
            SuffixTreeNode* child = curr->children[c];
            int edgeLen = child->end - child->start;
            int matchLen = 0;
            
            // Сравниваем вдоль ребра
            while (matchLen < edgeLen && pos + matchLen < (int)s.size() &&
                   s[child->start + matchLen] == s[pos + matchLen]) {
                matchLen++;
            }
            
            if (matchLen == edgeLen) {
                // Прошли всё ребро, спускаемся дальше
                curr = child;
                pos += matchLen;
            } else {
                // Расщепляем ребро
                SuffixTreeNode* mid = new SuffixTreeNode(child->start, child->start + matchLen);
                curr->children[c] = mid;
                
                // Старый ребёнок становится правым потомком mid
                child->start += matchLen;
                mid->children[s[child->start]] = child;
                
                // Новый лист
                SuffixTreeNode* leaf = new SuffixTreeNode(pos + matchLen, s.size());
                leaf->suffix_index = suffixStart;
                mid->children[s[pos + matchLen]] = leaf;
                return;
            }
        }
    }
    
public:
    NaiveSuffixTree(const std::string& str) : s(str) {
        root = new SuffixTreeNode(-1, -1);
        for (int i = 0; i < (int)s.size(); ++i) {
            insertSuffix(i);
        }
    }
};
```

### Сложность наивного алгоритма

Каждый из $n$ суффиксов может потребовать спуска на глубину до $O(n)$ с посимвольным сравнением.

$$T_{naive}(n) = \sum_{i=0}^{n-1} O(n - i) = O(n^2)$$

Это неприемлемо для больших строк, но полезно для понимания структуры и проверки корректности.

## 5. Обобщённые суффиксные деревья

### Определение
**Обобщённое суффиксное дерево (Generalized Suffix Tree, GST)** — это суффиксное дерево, построенное одновременно для **множества строк** $\{S_1, S_2, \ldots, S_k\}$.

### Построение
1. Конкатенируем строки с уникальными терминальными символами: $S_1\$1 S_2\$2 \ldots S_k\$k$.
2. Строим обычное суффиксное дерево для этой конкатенации.
3. Каждый лист помечаем идентификатором строки, которой принадлежит суффикс.

### Применение
- Поиск **наибольшей общей подстроки (LCS)** нескольких строк: ищем самый глубокий внутренний узел, в поддереве которого присутствуют листья всех строк.
- Поиск общих паттернов в наборе текстов.
- Сравнение геномов в биоинформатике.

### Сложность
Для $k$ строк суммарной длины $N$: построение за $O(N)$ (алгоритмом Укконена), память $O(N)$.

## 6. Резюме для экзамена

| Аспект | Ответ |
| :--- | :--- |
| **Суффиксное дерево** | Сжатое дерево всех суффиксов строки. $O(n)$ узлов и рёбер. Рёбра хранят $(start, len)$ |
| **Неявное дерево** | Промежуточная структура без явных листьев для всех суффиксов. Основа алгоритма Укконена |
| **Наивное построение** | Вставка каждого суффикса по отдельности. $O(n^2)$ времени, $O(n)$ памяти |
| **Обобщённое дерево** | Дерево для множества строк с уникальными терминаторами. LCS, общие паттерны |
| **Терминальный символ** | Обязателен (`$`) для однозначности: каждый суффикс → уникальный лист |
| **Память** | $O(n)$ благодаря хранению указателей на исходную строку, а не копий подстрок |

> **На экзамене обязательно:** Нарисовать пример суффиксного дерева для короткой строки (например, `abcabx$`), объяснить роль `$`, показать расщепление ребра в наивном алгоритме, и объяснить разницу между явным и неявным деревом.
