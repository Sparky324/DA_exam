# Вопрос 19. Алгоритм Ахо-Корасик. Доказательство линейности алгоритма. Приложения: задача о поиске с джокером

---

## 1. Определение и идея

**Алгоритм Ахо-Корасик (Aho-Corasick)** — это алгоритм поиска **множества образцов** в тексте за линейное время. Он строит на основе набора паттернов конечный автомат, который обрабатывает текст посимвольно, одновременно отслеживая все возможные совпадения.

> **Главное преимущество:** Время работы $O(n + m + z)$, где $n$ — длина текста, $m$ — суммарная длина всех образцов, $z$ — количество найденных вхождений. Не зависит от количества паттеров $k$!

### Основные компоненты автомата:
1.  **Trie (бор)** — дерево префиксов всех образцов.
2.  **Суффиксные ссылки (failure links)** — для каждого узла указывают на самый длинный собственный суффикс пути от корня, который также является путём в боре. Аналог префикс-функции KMP для дерева.
3.  **Выходные ссылки (output/dictionary suffix links)** — указывают на ближайший терминальный узел по цепочке суффиксных ссылок. Позволяют быстро находить все завершившиеся паттерны.
4.  **Функция перехода (go)** — $\text{go}(v, c)$ = следующий узел при чтении символа $c$ из состояния $v$. Если ребра нет, переходим по суффиксной ссылке (или остаёмся в корне).

## 2. Построение автомата (C++)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <queue>

const int ALPHA = 26; // a-z

struct Node {
    int children[ALPHA];      // Индексы детей (-1 если нет)
    int fail;                 // Суффиксная ссылка
    int output;               // Выходная ссылка (ближайший терминальный предок по fail)
    int pattern_id;           // ID паттерна, заканчивающегося здесь (-1 если не терминальный)
    bool is_terminal;

    Node() : fail(0), output(-1), pattern_id(-1), is_terminal(false) {
        std::fill(children, children + ALPHA, -1);
    }
};

std::vector<Node> trie;

// Добавление одного паттерна в бор
void addPattern(const std::string& s, int id) {
    int v = 0;
    for (char c : s) {
        int ch = c - 'a';
        if (trie[v].children[ch] == -1) {
            trie[v].children[ch] = trie.size();
            trie.emplace_back();
        }
        v = trie[v].children[ch];
    }
    trie[v].is_terminal = true;
    trie[v].pattern_id = id;
}

// Построение суффиксных и выходных ссылок (BFS)
void buildAutomaton() {
    std::queue<int> q;
    
    // Инициализация: дети корня → сам корень
    for (int c = 0; c < ALPHA; ++c) {
        if (trie[0].children[c] != -1) {
            trie[trie[0].children[c]].fail = 0;
            trie[trie[0].children[c]].output = -1;
            q.push(trie[0].children[c]);
        } else {
            trie[0].children[c] = 0; // go(root, c) = root если нет ребра
        }
    }
    
    // BFS по всем узлам
    while (!q.empty()) {
        int v = q.front(); q.pop();
        
        // Вычисляем output: ближайший терминальный по цепочке fail
        if (trie[trie[v].fail].is_terminal) {
            trie[v].output = trie[v].fail;
        } else {
            trie[v].output = trie[trie[v].fail].output;
        }
        
        for (int c = 0; c < ALPHA; ++c) {
            int u = trie[v].children[c];
            if (u != -1 && u != 0) { // Реальный ребёнок (не заглушка на корень)
                // Суффиксная ссылка: идём по fail родителя, пока не найдём ребро c
                int f = trie[v].fail;
                trie[u].fail = trie[f].children[c]; // go(fail(v), c) уже вычислено!
                
                q.push(u);
            } else if (u == -1) {
                // Заглушка: go(v, c) = go(fail(v), c)
                trie[v].children[c] = trie[trie[v].fail].children[c];
            }
        }
    }
}
```

> **Важный трюк:** После построения массив `children` превращается в полную таблицу переходов `go`. Для отсутствующих рёбер мы записываем переход по суффиксной ссылке, поэтому во время поиска **не нужно ходить по fail-ссылкам** — просто `v = go(v, c)` за $O(1)$.

## 3. Поиск в тексте

```cpp
// Возвращает список пар (позиция_в_тексте, id_паттерна)
std::vector<std::pair<int,int>> search(const std::string& text) {
    std::vector<std::pair<int,int>> results;
    int v = 0;
    
    for (int i = 0; i < (int)text.size(); ++i) {
        int c = text[i] - 'a';
        v = trie[v].children[c]; // O(1) благодаря предвычисленным переходам
        
        // Проверяем все паттерны, заканчивающиеся в текущей позиции
        int u = v;
        if (trie[u].is_terminal) {
            results.push_back({i, trie[u].pattern_id});
        }
        // Проходим по выходным ссылкам
        u = trie[u].output;
        while (u != -1) {
            results.push_back({i, trie[u].pattern_id});
            u = trie[u].output;
        }
    }
    
    return results;
}
```

## 4. Доказательство линейности алгоритма

> **Теорема.** Алгоритм Ахо-Корасик работает за время $O(n + m + z)$, где $n$ — длина текста, $m$ — суммарная длина паттернов, $z$ — число вхождений.

### Доказательство

Разделим работу алгоритма на три фазы:

**Фаза 1: Построение бора.**
Каждый символ каждого паттерна добавляется ровно один раз. Время: $O(m)$.

**Фаза 2: Построение ссылок (BFS).**
Каждый узел обрабатывается один раз. Для каждого узла перебирается $|\Sigma|$ символов. Время: $O(|\text{nodes}| \cdot |\Sigma|) = O(m \cdot |\Sigma|)$. При фиксированном алфавите: $O(m)$.

**Фаза 3: Поиск по тексту.**
Основной цикл делает $n$ итераций. На каждой итерации:
- Переход `go(v, c)` выполняется за $O(1)$ (предвычислен).
- Обработка выходов: проход по цепочке output-ссылок.

**Оценка прохода по output-ссылкам:**
Каждая output-ссылка ведёт к строго более короткому суффиксу. Длина цепочки output-ссылок из узла $v$ не превышает глубину $v$ в боре. Однако простая оценка «глубина × n» даёт $O(nm)$.

Более точная оценка: каждое найденное вхождение соответствует уникальной паре (позиция в тексте, паттерн). Общее число таких пар равно $z$. Каждый элемент цепочки output выдаёт хотя бы одно вхождение. Следовательно, суммарное число проходов по output-ссылкам за весь поиск равно $O(z)$.

**Итого:** $O(m \cdot |\Sigma| + n + z) = O(n + m + z)$ при фиксированном алфавите. $\blacksquare$

## 5. Приложение: Поиск с джокером (Wildcard Matching)

### Задача
Дан текст $T$ длины $n$ и образец $P$ длины $m$, содержащий обычные символы и специальные символы-джокеры (`?` или `*`), которые заменяют любой символ (или любую подстроку). Найти все позиции в $T$, где $P$ совпадает с учётом джокеров.

### Решение через Ахо-Корасик (для `?` как single-char wildcard)

Если джокер заменяет **ровно один** произвольный символ, задачу можно свести к множественному поиску:

1. Разбиваем $P$ на максимальные подстроки без джокеров: $P = s_1 \, ? \, s_2 \, ?? \, s_3 \ldots$
2. Собираем все непустые фрагменты $s_i$ и их относительные позиции в паттерне.
3. Строим автомат Ахо-Корасик для множества $\{s_1, s_2, s_3, \ldots\}$.
4. Прогоняем текст через автомат. Для каждого найденного вхождения фрагмента $s_i$ в позиции $pos$ проверяем, соответствует ли оно ожидаемому смещению внутри паттерна. Используем счётчик совпадений фрагментов для каждой потенциальной стартовой позиции паттерна в тексте.
5. Позиция $j$ текста является началом совпадения, если счётчик для $j$ равен числу фрагментов.

**Сложность:** $O(n + m + z')$, где $z'$ — число вхождений фрагментов. В худшем случае $z' = O(n \cdot k)$, но на практике значительно меньше.

### Для `*` (multi-char wildcard)
Задача сложнее. Обычно решается через комбинацию Ахо-Корасика (для якорных фрагментов между `*`) и проверки расстояний между ними. Либо через регулярные выражения / NFA.

## 6. Резюме для экзамена

| Аспект | Ответ |
| :--- | :--- |
| **Что такое AC** | Автомат для одновременного поиска множества паттернов в тексте |
| **Структура** | Trie + суффиксные ссылки (fail) + выходные ссылки (output) + таблица go |
| **Построение** | BFS по бору, $O(m \cdot |\Sigma|)$ |
| **Поиск** | Посимвольный проход по go + сбор выходов по output, $O(n + z)$ |
| **Доказательство линейности** | Построение $O(m)$, переходы $O(n)$, выходы суммарно $O(z)$ |
| **Применение: джокеры** | Разбиение паттерна на фрагменты без `?`, поиск фрагментов через AC, проверка позиций |
| **Общая сложность** | $O(n + m + z)$ |

> **На экзамене обязательно:** Объяснить роль каждой из трёх ссылок (fail, output, go), нарисовать пример небольшого автомата, и доказать линейность через разделение на фазы с оценкой суммы проходов по output-ссылкам как $O(z)$.
