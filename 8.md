# Вопрос 8. Декартовы деревья (Treap). Основные операции. Операции split и merge. Оценка алгоритмической сложности выполнения операций.

---

## 1. Определение и идея

**Декартово дерево (Cartesian Tree)**, в русскоязычной традиции чаще называемое **Дерамида (Treap = Tree + Heap)** — это бинарное дерево поиска, в котором каждому узлу присвоены два ключа:
1. **$x$ (key / ключ)** — по нему дерево является корректным **бинарным деревом поиска (BST)**.
2. **$y$ (priority / приоритет)** — по нему дерево является корректной **кучей (Heap)**. Обычно используется max-heap (приоритет родителя больше приоритетов потомков).

> **Главная фишка:** Если ключи $x$ могут быть любыми, то приоритеты $y$ выбираются **случайно** (например, из генератора псевдослучайных чисел). Благодаря этому дерево с высокой вероятностью автоматически получается сбалансированным, и его высота составляет $O(\log n)$. Нам не нужны сложные правила балансировки, как в AVL или RB-деревьях!

### Структура узла (C++)

```cpp
#include <iostream>
#include <cstdlib>
#include <ctime>
#include <utility>

struct Node {
    int key;        // x - ключ BST
    int priority;   // y - приоритет кучи
    Node* left;
    Node* right;

    Node(int k) : key(k), priority(rand()), left(nullptr), right(nullptr) {}
};

using pnode = Node*;
```

## 2. Вариации декартовых деревьев

Перед тем как переходить к операциям, важно упомянуть вариации, так как термин «декартово дерево» имеет несколько значений.

### 2.1. Классическое декартово дерево (по массиву)
Строится за $O(n)$ для заданного массива чисел. Ключ $x$ — это индекс элемента в массиве, а приоритет $y$ — само значение элемента. Строится с помощью стека за один проход слева направо. Используется для решения задач RMQ (Range Minimum Query) и построения суффиксных деревьев (алгоритм Фараха-Колтона-Бендера).

### 2.2. Treap (Дерамида) — рандомизированное BST
Именно этот вариант подразумевается в курсе «Дискретный анализ» при упоминании `split` и `merge`. Приоритеты генерируются случайно.

### 2.3. Неявное декартово дерево (Implicit Treap) — вопрос 9
Вместо явного ключа $x$ позиция элемента определяется **размером его левого поддерева**. Позволяет работать с массивом как с динамической структурой (вставка/удаление по индексу, разворот отрезка за $O(\log n)$).

## 3. Основные операции: Split и Merge

Вся мощь Treap заключается в том, что все остальные операции (вставка, удаление, поиск) реализуются через две базовые: **Split (разделение)** и **Merge (слияние)**.

### 3.1. Операция Merge (Слияние)

**Задача:** Даны два Treap'а $L$ и $R$. Известно, что **все** ключи в $L$ меньше **всех** ключей в $R$. Нужно объединить их в один Treap.

**Алгоритм:**
1. Если одно из деревьев пусто, возвращаем другое.
2. Сравниваем приоритеты корней $L$ и $R$.
3. У кого приоритет **больше**, тот становится новым корнем (свойство кучи).
4. Пусть корень $L$ больше. Тогда левый потомок нового корня остаётся $L.left$, а вот правым потомком должен стать результат слияния $L.right$ и $R$ (так как все ключи в $L.right$ всё ещё меньше ключей в $R$).
5. Рекурсивно вызываем `merge`.

**Код на C++:**

```cpp
// Сливаем L и R. Гарантируется, что max_key(L) < min_key(R)
pnode merge(pnode L, pnode R) {
    if (!L) return R;
    if (!R) return L;

    if (L->priority > R->priority) {
        // L становится корнем, его правый потомок сливается с R
        L->right = merge(L->right, R);
        return L;
    } else {
        // R становится корнем, его левый потомок сливается с L
        R->left = merge(L, R->left);
        return R;
    }
}
```

### 3.2. Операция Split (Разделение)

**Задача:** Дан Treap $T$ и ключ $k$. Нужно разделить $T$ на два Treap'а: $L$ (все ключи $\leq k$) и $R$ (все ключи $> k$).

**Алгоритм:**
1. Если дерево пусто, возвращаем два пустых дерева.
2. Смотрим на ключ текущего корня `root->key`.
3. **Если `root->key <= k`:** Корень и всё его левое поддерево гарантированно уходят в $L$. А вот правое поддерево нужно рекурсивно разделить по тому же ключу $k$. Та часть правого поддерева, что $\leq k$, присоединяется к $L$ (как правый потомок корня), а та, что $> k$, уходит в $R$.
4. **Если `root->key > k`:** Корень и всё его правое поддерево уходят в $R$. Левое поддерево делим рекурсивно. Меньшая часть идёт в $L$, большая присоединяется к $R$ (как левый потомок корня).

**Код на C++:**

```cpp
// Разделяем T на L (<= key) и R (> key)
void split(pnode T, int key, pnode& L, pnode& R) {
    if (!T) {
        L = R = nullptr;
        return;
    }

    if (T->key <= key) {
        // T и его левое поддерево идут в L
        // Правое поддерево нужно разделить
        pnode l_sub, r_sub;
        split(T->right, key, l_sub, r_sub);
        
        T->right = l_sub; // меньшая часть правого поддерева цепляется к T
        L = T;
        R = r_sub;        // большая часть уходит в R
    } else {
        // T и его правое поддерево идут в R
        // Левое поддерево нужно разделить
        pnode l_sub, r_sub;
        split(T->left, key, l_sub, r_sub);
        
        T->left = r_sub;  // большая часть левого поддерева цепляется к T
        R = T;
        L = l_sub;        // меньшая часть уходит в L
    }
}
```

## 4. Остальные основные операции (через Split/Merge)

### 4.1. Поиск (Search)

Поиск выполняется точно так же, как в обычном BST (вопрос 5), без использования приоритетов.

```cpp
pnode search(pnode root, int key) {
    if (!root || root->key == key) return root;
    if (key < root->key) return search(root->left, key);
    return search(root->right, key);
}
```

### 4.2. Вставка (Insert)

**Идея:** Чтобы вставить новый узел с ключом $k$:
1. Делаем `split(root, k, L, R)`. Теперь в $L$ всё, что $\leq k$, в $R$ всё, что $> k$.
2. Создаём новый узел $M$ с ключом $k$ и случайным приоритетом.
3. Сначала сливаем $L$ и $M$: `temp = merge(L, M)`.
4. Затем сливаем `temp` и $R$: `root = merge(temp, R)`.

*(Примечание: если дубликаты не допускаются, нужно делать `split` строго по границам, но суть та же).*

```cpp
pnode insert(pnode root, int key) {
    pnode newNode = new Node(key);
    
    pnode L, R;
    split(root, key, L, R);      // разделяем
    
    pnode temp = merge(L, newNode); // сливаем левую часть с новым узлом
    root = merge(temp, R);          // сливаем с правой частью
    
    return root;
}
```

### 4.3. Удаление (Delete)

**Идея:** Чтобы удалить узел с ключом $k$:
1. Разбиваем дерево на три части: $< k$, $= k$, $> k$.
   - `split(root, k - 1, L, temp)` -> $L$ содержит $< k$, $temp$ содержит $\geq k$.
   - `split(temp, k, M, R)` -> $M$ содержит $= k$ (это удаляемый узел/узлы), $R$ содержит $> k$.
2. Удаляем корень дерева $M$ (или просто игнорируем его).
3. Сливаем оставшиеся части: `root = merge(L, R)`.

```cpp
pnode remove(pnode root, int key) {
    pnode L, temp, M, R;
    
    // Разделяем на < key и >= key
    split(root, key - 1, L, temp);
    // Разделяем >= key на == key и > key
    split(temp, key, M, R);
    
    // M - это узел(ы) с искомым ключом. 
    // Мы просто его "отбрасываем" (на практике нужно delete M, чтобы избежать утечки)
    if (M) {
        // Если M может быть деревом (несколько одинаковых ключей), 
        // можно слить его детей: M = merge(M->left, M->right); delete M;
        delete M; 
    }
    
    // Склеиваем обратно левую и правую части
    root = merge(L, R);
    
    return root;
}
```

## 5. Оценка алгоритмической сложности

Все операции (`insert`, `remove`, `search`) сводятся к вызовам `split` и `merge`. Поэтому сложность всех операций равна сложности `split` и `merge`.

Операции `split` и `merge` спускаются по дереву от корня к листьям. На каждом шаге мы идём только в одного из потомков. Следовательно, время работы `split` и `merge` пропорционально **высоте дерева** $h$:
$$T_{\text{split}} = O(h), \quad T_{\text{merge}} = O(h)$$

### Теорема о высоте Treap

> **Теорема.** Математическое ожидание высоты декартова дерева (Treap), построенного на $n$ узлах со случайными уникальными приоритетами, равно $O(\log n)$.

**Доказательство (идея):**
Структура Treap полностью определяется приоритетами. Если приоритеты — это случайная перестановка чисел от 1 до $n$, то процесс построения Treap эквивалентен построению обычного BST, в который элементы вставляются в **случайном порядке** (элемент с наибольшим приоритетом будет корнем, и т.д.).

Известно (и доказывается через гармонические ряды или индикаторные случайные величины), что математическое ожидание высоты случайного BST из $n$ элементов равно:
$$E[h] = O(\log n)$$
Точнее, $E[h] \approx 2.99 \log_2 n$ (теорема Рида-Девруа).

Таким образом, ожидаемая глубина рекурсии в `split` и `merge` есть $O(\log n)$.

### Итоговая таблица сложности

| Операция | Средняя сложность | Худший случай | Примечание |
| :--- | :--- | :--- | :--- |
| **Поиск** | $O(\log n)$ | $O(n)$ | Как в обычном BST |
| **Вставка** | $O(\log n)$ | $O(n)$ | 2 вызова split/merge |
| **Удаление** | $O(\log n)$ | $O(n)$ | 2 вызова split/merge |
| **Split** | $O(\log n)$ | $O(n)$ | Проход по одному пути вниз |
| **Merge** | $O(\log n)$ | $O(n)$ | Проход по одному пути вниз |

> **Худший случай $O(n)$** наступает, если приоритеты оказались неудачными (например, отсортированными). Но вероятность этого экспоненциально мала ($1/n!$). На практике Treap работает стабильно за $O(\log n)$.

## 6. Полный пример использования (C++)

```cpp
void printInOrder(pnode root) {
    if (!root) return;
    printInOrder(root->left);
    std::cout << root->key << "(p=" << root->priority << ") ";
    printInOrder(root->right);
}

int main() {
    srand(time(0));
    pnode root = nullptr;

    // Вставка
    root = insert(root, 10);
    root = insert(root, 5);
    root = insert(root, 15);
    root = insert(root, 3);
    root = insert(root, 7);

    std::cout << "In-order обход (должны быть отсортированы):\n";
    printInOrder(root);
    std::cout << "\n\n";

    // Поиск
    int findKey = 7;
    pnode found = search(root, findKey);
    std::cout << "Поиск " << findKey << ": " << (found ? "Найден" : "Не найден") << "\n";

    // Удаление
    root = remove(root, 5);
    std::cout << "После удаления 5:\n";
    printInOrder(root);
    std::cout << "\n";

    return 0;
}
```

## 7. Резюме для экзамена

1. **Treap (декартово дерево)** — структура данных, где каждый узел имеет ключ $x$ (свойство BST) и приоритет $y$ (свойство кучи). Приоритеты генерируются случайно.
2. **Базовые операции:** Вся логика строится на двух функциях:
   - **`split(T, k)`** — делит дерево на два: с ключами $\leq k$ и $> k$.
   - **`merge(L, R)`** — сливает два дерева, если все ключи $L$ меньше ключей $R$.
3. **Вставка и удаление** реализуются тривиальной комбинацией `split` и `merge` без написания сложных поворотов (в отличие от AVL/RB).
4. **Сложность:** Поскольку приоритеты случайны, дерево эквивалентно случайному BST. Его ожидаемая высота $O(\log n)$, поэтому `split`, `merge`, вставка, удаление и поиск работают в среднем за **$O(\log n)$**.
