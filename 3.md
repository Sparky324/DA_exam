# Вопрос 3. Поразрядная сортировка (Radix Sort). Доказательство линейности алгоритма.

---

## 1. Идея алгоритма

Поразрядная сортировка — это алгоритм сортировки, который **не использует сравнения** элементов между собой. Он сортирует числа (или строки) **поразрядно**, то есть обрабатывает ключи по одному разряду (цифре, байту, символу) за проход.

> Как и сортировка подсчётом (вопрос 2), Radix Sort обходит нижнюю границу $\Omega(n \log n)$ для сортировок сравнением, так как не сравнивает элементы напрямую.

Ключевое требование: для сортировки по отдельным разрядам должна использоваться **стабильная** сортировка (чаще всего — стабильная сортировка подсчётом). Если подпрограмма нестабильна, порядок элементов, отсортированных по младшим разрядам, будет разрушен при сортировке по старшим.

## 2. Вариации поразрядной сортировки

В литературе (Кормен, Кнут, Седжвик) выделяют несколько классификаций вариаций этого алгоритма. На экзамене важно знать их все.

### 2.1. По направлению обработки разрядов

#### A. LSD (Least Significant Digit) — от младшего к старшему
-   **Как работает:** Сначала сортируем массив по самому младшему разряду (единицы), затем по следующему (десятки) и так далее до самого старшего разряда.
-   **Требование:** Внутренняя сортировка **обязана быть стабильной**.
-   **Применение:** Идеально подходит для целых чисел фиксированной длины и строк одинаковой длины.
-   **Особенность:** Не требует рекурсии.

#### B. MSD (Most Significant Digit) — от старшего к младшему
-   **Как работает:** Сначала сортируем по самому старшему разряду. Затем массив разбивается на «карманы» (группы с одинаковым старшим разрядом), и каждый карман **рекурсивно** сортируется по следующему разряду.
-   **Требование:** Стабильность желательна, но не строго обязательна (зависит от реализации), так как карманы обрабатываются независимо.
-   **Применение:** Строки переменной длины, большие массивы данных.
-   **Особенность:** Может прерваться досрочно! Если в каком-то кармане остался 1 элемент или все элементы равны, рекурсия останавливается, даже если мы не дошли до младшего разряда. Это делает MSD очень быстрым на практике для строк.

### 2.2. По выбору основания системы счисления (radix / база $R$)

База $R$ определяет, сколько возможных значений принимает один «разряд».

-   **$R = 10$ (Десятичная):** Разряд — это цифра от 0 до 9. Понятно для человека, но не оптимально для компьютера.
-   **$R = 2$ (Бинарная):** Разряд — это один бит. Требуется много проходов ($d = 32$ или $64$ для `int`/`long long`).
-   **$R = 256$ (Байтовая):** Разряд — это 1 байт (8 бит). Для 32-битного `int` нужно ровно 4 прохода. Самая частая реализация на практике.
-   **$R = 2^{16} = 65536$:** Разряд — 2 байта (16 бит). Для 32-битного `int` нужно всего 2 прохода, но массив подсчётов `count` будет большим (65536 элементов).
-   **Выбор $R$** — это компромисс между количеством проходов $d$ и размером памяти/временем на очистку массива `count`. Оптимально часто брать $R \approx n$ или степень двойки, близкую к $n$.

### 2.3. По типу данных

-   **Целые числа:** Обрабатываем биты/байты. Для отрицательных чисел (дополнительный код) обычно сначала сортируют как беззнаковые, а затем циклически сдвигают массив, чтобы отрицательные оказались перед положительными.
-   **Строки:** Используется только MSD-подход, так как строки имеют разную длину. Отсутствие символа трактуется как значение меньше любого существующего символа.
-   **Числа с плавающей точкой (float/double):** IEEE 754 представление можно хитро преобразовать (инвертировать знаковый бит и, если число отрицательное, инвертировать все биты), чтобы побитовая сортировка работала корректно.

## 3. Простой код на C++ (LSD Radix Sort, база 10)

Это самая понятная для экзамена реализация. Используем стабильную сортировку подсчётом для каждого разряда.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

// Вспомогательная функция: стабильная сортировка подсчётом по конкретному разряду
// exp = 1 (единицы), 10 (десятки), 100 (сотни) и т.д.
void countingSortByDigit(std::vector<int>& arr, int exp) {
    int n = arr.size();
    std::vector<int> output(n);
    std::vector<int> count(10, 0); // База R = 10, цифры от 0 до 9

    // 1. Подсчёт
    for (int i = 0; i < n; ++i) {
        int digit = (arr[i] / exp) % 10;
        count[digit]++;
    }

    // 2. Префиксные суммы
    for (int i = 1; i < 10; ++i) {
        count[i] += count[i - 1];
    }

    // 3. Расстановка (справа налево для стабильности!)
    for (int i = n - 1; i >= 0; --i) {
        int digit = (arr[i] / exp) % 10;
        output[count[digit] - 1] = arr[i];
        count[digit]--;
    }

    // 4. Копируем обратно
    arr = output;
}

// Основная функция LSD Radix Sort
void radixSortLSD(std::vector<int>& arr) {
    if (arr.empty()) return;

    // Находим максимум, чтобы знать, сколько разрядов обрабатывать
    int max_val = *std::max_element(arr.begin(), arr.end());

    // Проходим по всем разрядам: единицы, десятки, сотни...
    for (int exp = 1; max_val / exp > 0; exp *= 10) {
        countingSortByDigit(arr, exp);
    }
}

int main() {
    std::vector<int> arr = {170, 45, 75, 90, 802, 24, 2, 66};

    std::cout << "До: ";
    for (int x : arr) std::cout << x << " ";
    std::cout << "\n";

    radixSortLSD(arr);

    std::cout << "После: ";
    for (int x : arr) std::cout << x << " ";
    std::cout << "\n";

    return 0;
}
```

### Вывод:
```
До: 170 45 75 90 802 24 2 66 
После: 2 24 45 66 75 90 170 802 
```

## 4. Код на C++ (MSD Radix Sort для строк)

Чтобы показать знание вариаций, приведу простую рекурсивную реализацию MSD для строк.

```cpp
#include <iostream>
#include <vector>
#include <string>

void msdRadixSortHelper(std::vector<std::string>& arr, int left, int right, int charIndex) {
    if (left >= right) return;

    // Создаём 257 карманов: 0 - для строк, которые уже закончились, 1..256 - для символов
    std::vector<std::vector<std::string>> buckets(257);

    for (int i = left; i <= right; ++i) {
        if (charIndex >= (int)arr[i].length()) {
            buckets[0].push_back(arr[i]); // Строка короче текущего индекса
        } else {
            buckets[(unsigned char)arr[i][charIndex] + 1].push_back(arr[i]);
        }
    }

    int idx = left;
    for (int b = 0; b < 257; ++b) {
        for (const auto& s : buckets[b]) {
            arr[idx++] = s;
        }
        // Рекурсивно сортируем карманы (кроме нулевого, там строки уже на своём месте)
        if (b > 0 && buckets[b].size() > 1) {
            // Вычисляем границы для рекурсии
            int newLeft = idx - (int)buckets[b].size();
            int newRight = idx - 1;
            msdRadixSortHelper(arr, newLeft, newRight, charIndex + 1);
        }
    }
}

void msdRadixSort(std::vector<std::string>& arr) {
    if (arr.empty()) return;
    msdRadixSortHelper(arr, 0, (int)arr.size() - 1, 0);
}
```

## 5. Доказательство линейности алгоритма

Пусть:
-   $n$ — количество элементов в массиве.
-   $d$ — количество разрядов в максимальном числе (количество проходов).
-   $R$ — основание системы счисления (база, размер алфавита разряда, например, $R=10$ или $R=256$).

### Шаг 1: Оценка одного прохода
Каждый проход Radix Sort представляет собой вызов сортировки подсчётом для одного разряда.
Как доказано в вопросе 2, сортировка подсчётом массива из $n$ элементов со значениями от $0$ до $R-1$ работает за время:
$$T_{\text{pass}} = O(n + R)$$

### Шаг 2: Оценка всех проходов
Алгоритм выполняет ровно $d$ проходов (от младшего разряда к старшему в LSD, или наоборот в MSD без учёта досрочного выхода).
Общее время работы:
$$T(n, d, R) = d \cdot O(n + R) = O(d \cdot (n + R))$$

### Шаг 3: Условия линейности
Алгоритм считается **линейным**, если его сложность равна $O(n)$.
Для этого необходимо, чтобы $d$ и $R$ были константами или выражались через $n$ так, чтобы итоговая формула свелась к $O(n)$.

**Случай 1: Фиксированный тип данных (например, 32-битные `int`)**
Если мы сортируем стандартные 32-битные целые числа и выбираем базу $R = 256$ (сортируем по байтам):
-   Количество разрядов $d = 32 / 8 = 4$ (константа).
-   Размер базы $R = 256$ (константа).
-   Тогда:
$$T(n) = O(4 \cdot (n + 256)) = O(n)$$
**Доказано, что для чисел фиксированной разрядности алгоритм линеен.** $\blacksquare$

**Случай 2: Произвольные числа, выбор оптимальной базы**
Пусть максимальное число в массиве равно $M$. Тогда количество разрядов в базе $R$ равно:
$$d = \lceil \log_R M \rceil = \left\lceil \frac{\log_2 M}{\log_2 R} \right\rceil$$
Подставим в формулу времени:
$$T(n) = O\left(\frac{\log M}{\log R} \cdot (n + R)\right)$$
Если мы выберем базу $R = n$, то:
$$T(n) = O\left(\frac{\log M}{\log n} \cdot (n + n)\right) = O\left(n \cdot \frac{\log M}{\log n}\right)$$
Если $M \leq n^c$ для некоторой константы $c$ (то есть числа полиномиально ограничены относительно $n$), то $\log M \leq c \log n$, и:
$$T(n) = O\left(n \cdot \frac{c \log n}{\log n}\right) = O(c \cdot n) = O(n)$$
**Доказано, что при правильном выборе базы $R=n$ и полиномиальном ограничении значений, алгоритм линеен.** $\blacksquare$

### Сложность по памяти:
Требуется место для выходного массива и массива подсчётов:
$$S(n, R) = O(n + R)$$
При $R = O(n)$ память также линейна: $O(n)$.

## 6. Сравнение LSD и MSD (для экзамена)

| Характеристика | LSD (младший -> старший) | MSD (старший -> младший) |
| :--- | :--- | :--- |
| **Направление** | Справа налево (по разрядам) | Слева направо (по разрядам) |
| **Рекурсия** | Нет (итеративный) | Да (рекурсивный) |
| **Стабильность** | Строго требуется | Не всегда критична |
| **Досрочное завершение** | Невозможно (всегда $d$ проходов) | Возможно (если карман пуст/размер 1) |
| **Лучшее применение** | Числа, строки одной длины | Строки разной длины, большие данные |
| **Кэш-локальность** | Хорошая (проход по всему массиву) | Хуже (рекурсивные прыжки по карманам) |

## 7. Резюме для экзамена

1. **Идея:** сортируем поразрядно, используя стабильную сортировку подсчётом как подпрограмму.
2. **Вариации:**
   - По направлению: **LSD** (от младшего к старшему) и **MSD** (от старшего к младшему, рекурсивно).
   - По базе: $R=10$, $R=256$ (байты), $R=2^{16}$ и т.д.
3. **Время работы:** $O(d \cdot (n + R))$, где $d$ — число разрядов, $R$ — база.
4. **Линейность:** Если $d$ и $R$ — константы (например, 32-битные числа, база 256), или если выбрать $R=n$ при $M \leq n^c$, то сложность становится **строго линейной** $O(n)$.
5. **Память:** $O(n + R)$.
6. **Не использует сравнений**, поэтому теорема из вопроса 1 здесь не применяется.
