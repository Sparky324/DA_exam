# Вопрос 18. Алгоритм Апостолико-Джанкарло. Доказательство линейности алгоритма

---

## 1. Мотивация и идея

**Алгоритм Апостолико-Джанкарло (Apostolico-Giancarlo, AG)** — это модификация алгоритма Бойера-Мура (вопрос 17), которая гарантирует **строгую линейность $O(n + m)$** в худшем случае без использования правила Галила.

### Проблема Бойера-Мура
В классическом BM при большом сдвиге по правилу хорошего суффикса мы можем «забыть», что часть текста уже была проверена и совпала с образцом. При следующем выравнивании эти символы проверяются повторно, что в патологических случаях (например, $T = a^n$, $P = a^{n/2}$) приводит к квадратичной сложности $O(nm)$.

### Решение AG
Алгоритм запоминает информацию о предыдущих совпадениях в специальном массиве `skip`. При очередном сравнении, если мы попадаем на позицию, которая уже была проверена как часть хорошего суффикса на предыдущем шаге, мы **не сравниваем символы заново**, а используем сохранённое значение.

> **Ключевое отличие от BM:** AG никогда не перепроверяет символы текста, которые уже были успешно сопоставлены. Это превращает амортизированную линейность BM в строгую линейность.

---

## 2. Предобработка

Алгоритму нужны две таблицы:
1.  **Таблица плохого символа** `last[c]` (как в BM).
2.  **Таблица хорошего суффикса** `gs[j]` (как в BM).
3.  **Массив `skip`** размера $m$ — хранит длину известного совпадения суффикса образца, заканчивающегося в данной позиции относительно текущего выравнивания. Изначально все нули.

Также используется массив `suff[i]` (суффиксная функция образца), где `suff[i]` = длина наибольшего общего суффикса $P[0..i]$ и всего образца $P$.

## 3. Алгоритм (C++)

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>

const int ALPHABET = 256;

// Таблица плохого символа
std::vector<int> buildBadChar(const std::string& p) {
    std::vector<int> last(ALPHABET, -1);
    for (int i = 0; i < (int)p.size(); ++i)
        last[(unsigned char)p[i]] = i;
    return last;
}

// Суффиксная функция образца
std::vector<int> computeSuffixes(const std::string& p) {
    int m = p.size();
    std::vector<int> suff(m, 0);
    suff[m - 1] = m;
    int g = m - 1, f = 0;
    for (int i = m - 2; i >= 0; --i) {
        if (i > g && suff[i + m - 1 - f] < i - g)
            suff[i] = suff[i + m - 1 - f];
        else {
            if (i < g) g = i;
            f = i;
            while (g >= 0 && p[g] == p[g + m - 1 - f]) g--;
            suff[i] = f - g;
        }
    }
    return suff;
}

// Таблица хорошего суффикса
std::vector<int> buildGoodSuffix(const std::string& p) {
    int m = p.size();
    auto suff = computeSuffixes(p);
    std::vector<int> gs(m, m);
    int j = 0;
    for (int i = m - 1; i >= 0; --i)
        if (suff[i] == i + 1)
            while (j < m - 1 - i) { if (gs[j] == m) gs[j] = m - 1 - i; j++; }
    for (int i = 0; i < m - 1; ++i)
        gs[m - 1 - suff[i]] = m - 1 - i;
    return gs;
}

// === Алгоритм Апостолико-Джанкарло ===
std::vector<int> agSearch(const std::string& text, const std::string& pattern) {
    std::vector<int> occ;
    int n = text.size(), m = pattern.size();
    if (m > n || m == 0) return occ;

    auto last = buildBadChar(pattern);
    auto gs   = buildGoodSuffix(pattern);
    auto suff = computeSuffixes(pattern);

    std::vector<int> skip(m, 0); // skip[j] = длина известного совпадения, 
                                  // заканчивающегося в позиции j образца
    int s = 0; // текущий сдвиг

    while (s <= n - m) {
        int j = m - 1;

        // Сравнение справа налево с использованием skip
        while (j >= 0) {
            if (skip[j] > 0) {
                // Мы уже знаем, что suffix длины skip[j] совпадает
                // Проверяем только границу
                if (skip[j] <= suff[j]) {
                    // Совпадение подтверждено, пропускаем skip[j] символов
                    j -= skip[j];
                } else {
                    // suff[j] < skip[j]: известное совпадение длиннее, 
                    // чем позволяет структура образца → несовпадение
                    break;
                }
            } else {
                // Обычное посимвольное сравнение
                if (pattern[j] == text[s + j]) {
                    j--;
                } else {
                    break; // несовпадение
                }
            }
        }

        if (j < 0) {
            // Полное совпадение
            occ.push_back(s);
            // Запоминаем совпадение для будущих шагов
            skip[m - 1] = m;
            s += gs[0];
        } else {
            // Несовпадение в позиции j
            // Запоминаем длину совпавшего суффикса
            int matched = m - 1 - j;
            if (matched > 0) {
                skip[j + matched] = matched; 
                // На самом деле нужно запоминать корректно:
                // Для каждой позиции k в совпавшем суффиксе
                // Но оптимизированная версия запоминает только ключевые точки
            }

            int bcShift = j - last[(unsigned char)text[s + j]];
            int gsShift = gs[j];
            s += std::max(1, std::max(bcShift, gsShift));
        }

        // Очистка skip для позиций, которые больше не актуальны
        // (упрощённо: сбрасываем при каждом сдвиге, 
        //  но в полной реализации очищаются только затронутые позиции)
        // В канонической версии AG skip обновляется инкрементально
    }

    return occ;
}
```

> **Примечание:** Выше приведена упрощённая иллюстрация идеи. Полная каноническая реализация AG требует аккуратного поддержания массива `skip` с учётом сдвигов. На экзамене достаточно описать принцип и доказать линейность.

## 4. Доказательство линейности алгоритма

> **Теорема.** Алгоритм Апостолико-Джанкарло выполняет не более $2n$ сравнений символов текста и работает за время $O(n + m)$.

### Доказательство

Введём два типа операций над символами текста:

**Тип A: Успешное сравнение** ($T[s+j] == P[j]$ или использование `skip`).
Каждое успешное сравнение соответствует некоторой позиции текста $T[i]$. Ключевое свойство AG: **каждая позиция текста участвует в успешном сравнении не более одного раза**. Если позиция была проверена и совпала на шаге $s_1$, то на любом последующем шаге $s_2 > s_1$ эта позиция либо пропускается через `skip`, либо никогда не проверяется снова (так как сдвиг всегда положительный, а `skip` предотвращает повторную проверку).

Следовательно, общее число успешных сравнений $\leq n$.

**Тип B: Неуспешное сравнение** ($T[s+j] \neq P[j]$).
Неуспешное сравнение происходит **ровно один раз на каждый сдвиг** $s$ (оно завершает фазу сравнения для данного выравнивания). Поскольку сдвиг всегда $\geq 1$, количество сдвигов $\leq n$, а значит, количество неуспешных сравнений $\leq n$.

**Итого:** Общее число сравнений символов $\leq n + n = 2n = O(n)$.

Предобработка (таблицы `last`, `gs`, `suff`) занимает $O(m + |\Sigma|)$. Поддержание массива `skip` также амортизированно $O(n)$, так как каждая запись в `skip` создаётся один раз и потребляется/сбрасывается один раз.

**Общее время работы: $O(n + m + |\Sigma|) = O(n + m)$** (при фиксированном алфавите). $\blacksquare$

| :--- | :--- | :--- | :--- | :--- |
| Наивный | $O(nm)$ | $O(n)$ | $O(1)$ | Простой, медленный в худшем |

## 6. Резюме для экзамена

1. **AG** — модификация Бойера-Мура с гарантированной линейностью $O(n+m)$.
2. **Идея:** Массив `skip` запоминает длины совпавших суффиксов, предотвращая повторные проверки одних и тех же позиций текста.
3. **Правила сдвига:** Те же, что в BM (bad character + good suffix), но фаза сравнения использует `skip` для пропуска известных совпадений.
4. **Доказательство линейности:** Каждое успешное сравнение привязано к уникальной позиции текста ($\leq n$), каждое неуспешное — к уникальному сдвигу ($\leq n$). Итого $\leq 2n$ сравнений.
5. **Преимущество перед BM:** Строгая линейность без правила Галила. **Недостаток:** Более сложная реализация и константы выше, чем у BM на практике.
