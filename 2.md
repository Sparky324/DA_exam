# Вопрос 2. Сортировка подсчётом (Counting Sort). Доказательство линейности алгоритма.

---

## 1. Идея алгоритма

Сортировка подсчётом — это алгоритм сортировки, который **не использует сравнения** элементов. Он работает за линейное время $O(n + k)$, но с важным ограничением: сортируемые элементы должны быть **целыми числами из небольшого диапазона** от $0$ до $k-1$ (или от $\min$ до $\max$, что легко сводится к нулю сдвигом).

> Поскольку алгоритм не основан на сравнениях, он **обходит нижнюю границу** $\Omega(n \log n)$ из вопроса 1.

### Алгоритм по шагам:

1. **Подсчёт:** создаём массив `count` размера $k$ (где $k = \max - \min + 1$) и считаем, сколько раз каждый элемент встречается во входном массиве.
2. **Префиксные суммы:** преобразуем `count` так, чтобы `count[i]` содержал количество элементов, **меньших или равных** `i`. Это покажет последнюю позицию, куда нужно поставить элемент со значением `i`.
3. **Расстановка (стабильная):** проходим исходный массив **справа налево** (это важно для стабильности!), смотрим в `count`, ставим элемент на нужную позицию в выходной массив и уменьшаем `count` на 1.

---

## 2. Простой код на C++

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

void countingSort(std::vector<int>& arr) {
    if (arr.empty()) return;

    // 1. Находим минимум и максимум
    int min_val = *std::min_element(arr.begin(), arr.end());
    int max_val = *std::max_element(arr.begin(), arr.end());
    int k = max_val - min_val + 1; // размер диапазона

    // 2. Массив подсчётов
    std::vector<int> count(k, 0);
    for (int x : arr) {
        count[x - min_val]++;
    }

    // 3. Префиксные суммы: count[i] теперь хранит, 
    //    сколько элементов <= i + min_val
    for (int i = 1; i < k; ++i) {
        count[i] += count[i - 1];
    }

    // 4. Расстановка в выходной массив (справа налево для стабильности)
    std::vector<int> output(arr.size());
    for (int i = (int)arr.size() - 1; i >= 0; --i) {
        int val = arr[i];
        int idx = val - min_val;
        
        // count[idx] - это номер позиции (1-based), куда ставить элемент
        output[count[idx] - 1] = val;
        count[idx]--;
    }

    // 5. Копируем результат обратно
    arr = output;
}

int main() {
    std::vector<int> arr = {4, 2, 2, 8, 3, 3, 1};
    
    std::cout << "До: ";
    for (int x : arr) std::cout << x << " ";
    std::cout << "\n";

    countingSort(arr);

    std::cout << "После: ";
    for (int x : arr) std::cout << x << " ";
    std::cout << "\n";

    return 0;
}
```

### Вывод:
```
До: 4 2 2 8 3 3 1 
После: 1 2 2 3 3 4 8 
```

## 3. Доказательство линейности алгоритма

Пусть $n$ — количество элементов в массиве, $k$ — размер диапазона значений (т.е. $k = \max - \min + 1$).

Оценим время работы каждого шага:

| Шаг | Описание | Время |
|-----|----------|-------|
| 1 | Поиск минимума и максимума | $O(n)$ |
| 2 | Создание и заполнение массива `count` нулями | $O(k)$ |
| 3 | Подсчёт вхождений (цикл по `arr`) | $O(n)$ |
| 4 | Вычисление префиксных сумм (цикл по `count`) | $O(k)$ |
| 5 | Расстановка элементов в `output` (цикл по `arr`) | $O(n)$ |
| 6 | Копирование `output` в `arr` | $O(n)$ |

**Итоговая сложность по времени:**
$$T(n, k) = O(n) + O(k) + O(n) + O(k) + O(n) + O(n) = O(n + k)$$

Если $k = O(n)$ (то есть диапазон значений не превышает порядок количества элементов, например, числа от $0$ до $n$), то:
$$T(n) = O(n + n) = O(n)$$

**Это доказывает линейность алгоритма.** $\blacksquare$

### Сложность по памяти:
Алгоритм требует дополнительного массива `count` размера $k$ и массива `output` размера $n$.
$$S(n, k) = O(n + k)$$
Поэтому сортировка подсчётом **не является in-place** (сортировкой на месте).

## 4. Почему алгоритм стабильный?

**Стабильность** означает, что равные элементы сохраняют свой относительный порядок из исходного массива.

В коде мы проходим исходный массив **справа налево** (от `n-1` до `0`). 
Когда мы встречаем элемент `val`, мы смотрим `count[val - min_val]` — это позиция **после последнего** такого элемента. Мы ставим его туда и уменьшаем счётчик. 

Так как мы идём справа налево, более правый элемент в исходном массиве будет поставлен правее в выходном массиве, а более левый — левее. Относительный порядок сохраняется.

> **Зачем нужна стабильность?** Сама по себе для целых чисел она не критична, но сортировка подсчётом используется как **подпрограмма в поразрядной сортировке (Radix Sort)** (вопрос 3), где стабильность жизненно необходима для корректности всего алгоритма.

## 5. Упрощённая версия (нестабильная)

Если нам нужно просто отсортировать числа (без объектов с ключами, где важна стабильность), код можно сильно упростить — вообще без префиксных сумм и выходного массива:

```cpp
void countingSortSimple(std::vector<int>& arr) {
    if (arr.empty()) return;

    int min_val = *std::min_element(arr.begin(), arr.end());
    int max_val = *std::max_element(arr.begin(), arr.end());
    
    std::vector<int> count(max_val - min_val + 1, 0);
    
    // Просто считаем
    for (int x : arr) count[x - min_val]++;
    
    // Перезаписываем исходный массив
    int idx = 0;
    for (int i = 0; i < (int)count.size(); ++i) {
        while (count[i] > 0) {
            arr[idx++] = i + min_val;
            count[i]--;
        }
    }
}
```
Эта версия тоже работает за $O(n + k)$ и расходует $O(k)$ дополнительной памяти, но **не является стабильной** (в контексте сортировки объектов по ключам). Для экзамена лучше знать и уметь объяснять именно классическую стабильную версию.

---

## 6. Резюме для экзамена

1. **Не использует сравнения**, поэтому обходит границу $\Omega(n \log n)$.
2. **Принцип:** подсчитать количество каждого значения, вычислить префиксные суммы, расставить элементы.
3. **Время:** $O(n + k)$, где $n$ — число элементов, $k$ — размер диапазона. Если $k = O(n)$, время **линейно** $O(n)$.
4. **Память:** $O(n + k)$.
5. **Стабильность:** обеспечивается проходом исходного массива справа налево при расстановке. Необходима для использования в Radix Sort.
