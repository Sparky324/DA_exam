# Вопрос 23. Суффиксные массивы. Алгоритм построения с использованием суффиксных деревьев. Поиск подстроки в строке с использованием суффиксного массива

---

## 1. Определение суффиксного массива

**Суффиксный массив (Suffix Array, SA)** для строки $S$ длины $n$ — это массив целых чисел $sa[0..n-1]$, содержащий индексы всех суффиксов строки $S$, **отсортированные в лексикографическом порядке**.

Формально:
$$S[sa[0]..] <_{lex} S[sa[1]..] <_{lex} \ldots <_{lex} S[sa[n-1]..]$$

### Пример
Для строки `banana$` (с терминальным символом `$` < `a`):

| Индекс суффикса | Суффикс     | Ранг в сортировке |
| :-------------- | :---------- | :---------------- |
| 6               | `$`         | 0                 |
| 5               | `a$`        | 1                 |
| 3               | `ana$`      | 2                 |
| 1               | `anana$`    | 3                 |
| 0               | `banana$`   | 4                 |
| 4               | `na$`       | 5                 |
| 2               | `nana$`     | 6                 |

Суффиксный массив: `sa = [6, 5, 3, 1, 0, 4, 2]`

### Сравнение с суффиксным деревом
-   Суффиксный массив занимает **в 3–5 раз меньше памяти**, чем суффиксное дерево (нет указателей на детей, суффиксных ссылок, меток рёбер).
-   Многие задачи, решаемые через суффиксное дерево, можно решить через SA + вспомогательный массив LCP (Longest Common Prefix).
-   Построение SA может быть выполнено за $O(n)$ без построения дерева (вопрос 24), но в данном вопросе рассматривается построение **через суффиксное дерево**.

## 2. Построение суффиксного массива через суффиксное дерево

### Идея
Суффиксное дерево содержит все суффиксы в лексикографическом порядке: если обойти листья дерева **in-order** (слева направо по символам на рёбрах), то получим именно суффиксный массив.

### Алгоритм
1. Построить суффиксное дерево для строки $S$ (например, алгоритмом Укконена за $O(n)$).
2. Выполнить DFS/in-order обход дерева, посещая детей каждого узла в порядке возрастания первого символа метки ребра.
3. При посещении листа записывать его `suffix_index` в массив `sa`.

### Код на C++

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <map>

// Упрощённая структура узла суффиксного дерева
struct STNode {
    std::map<char, STNode*> children; // map автоматически сортирует по char
    int suffix_index;                  // Только для листьев
    bool is_leaf;
    
    STNode() : suffix_index(-1), is_leaf(false) {}
};

// In-order обход: дети посещаются в лексикографическом порядке ключей map
void dfs(STNode* node, std::vector<int>& sa) {
    if (node->is_leaf) {
        sa.push_back(node->suffix_index);
        return;
    }
    for (auto& [c, child] : node->children) {
        dfs(child, sa);
    }
}

std::vector<int> buildSAFromSuffixTree(STNode* root, int n) {
    std::vector<int> sa;
    sa.reserve(n);
    dfs(root, sa);
    return sa;
}
```

### Сложность
- Построение суффиксного дерева: $O(n)$ (Укконен).
- Обход дерева: $O(n)$ (каждый узел и ребро посещается один раз).
- **Итого: $O(n)$**.

> **Важно:** Использование `std::map` даёт автоматическую сортировку детей по символу, что критично для корректного in-order обхода. Если используется массив/хеш-таблица, нужно явно сортировать детей перед обходом.

## 3. Поиск подстроки с использованием суффиксного массива

### Задача
Дан текст $T$ (построен SA) и образец $P$ длины $m$. Найти все вхождения $P$ в $T$.

### Наивный подход: бинарный поиск
Поскольку суффиксы в SA отсортированы, можно использовать **бинарный поиск** для нахождения границ диапазона суффиксов, начинающихся с $P$.

#### Алгоритм
1. Найти **левую границу** $lo$: наименьший индекс $i$ такой, что $T[sa[i]..]$ начинается с $P$.
2. Найти **правую границу** $hi$: наибольший индекс $i$ такой, что $T[sa[i]..]$ начинается с $P$.
3. Все позиции $sa[lo], sa[lo+1], \ldots, sa[hi]$ — начала вхождений $P$.

Каждое сравнение при бинарном поиске требует $O(m)$ времени (сравнение образца с суффиксом). Бинарный поиск делает $O(\log n)$ сравнений.

```cpp
// Сравнение: начинается ли суффикс T[pos..] с pattern?
int compare(const std::string& T, int pos, const std::string& P) {
    for (int i = 0; i < (int)P.size(); ++i) {
        if (pos + i >= (int)T.size()) return -1; // суффикс короче → меньше
        if (T[pos + i] < P[i]) return -1;
        if (T[pos + i] > P[i]) return 1;
    }
    return 0; // совпадение префикса
}

// Бинарный поиск левой границы
int lowerBound(const std::string& T, const std::vector<int>& sa, const std::string& P) {
    int lo = 0, hi = sa.size();
    while (lo < hi) {
        int mid = (lo + hi) / 2;
        if (compare(T, sa[mid], P) < 0)
            lo = mid + 1;
        else
            hi = mid;
    }
    return lo;
}

// Бинарный поиск правой границы
int upperBound(const std::string& T, const std::vector<int>& sa, const std::string& P) {
    int lo = 0, hi = sa.size();
    while (lo < hi) {
        int mid = (lo + hi) / 2;
        if (compare(T, sa[mid], P) <= 0)
            lo = mid + 1;
        else
            hi = mid;
    }
    return lo - 1;
}

std::vector<int> searchWithSA(const std::string& T, const std::vector<int>& sa, 
                               const std::string& P) {
    std::vector<int> result;
    int lo = lowerBound(T, sa, P);
    int hi = upperBound(T, sa, P);
    
    if (lo <= hi && lo < (int)sa.size()) {
        for (int i = lo; i <= hi; ++i)
            result.push_back(sa[i]);
    }
    return result;
}
```

### Сложность поиска
- Два бинарных поиска: $O(m \log n)$.
- Сбор результатов: $O(k)$, где $k$ — число вхождений.
- **Итого: $O(m \log n + k)$**.

### Улучшение до $O(m + \log n + k)$
С использованием массива **LCP** (Longest Common Prefix между соседними суффиксами в SA) и RMQ-структуры можно ускорить поиск:
1. Первый бинарный поиск: $O(m \log n)$.
2. Второй бинарный поиск можно заменить на расширение диапазона с использованием LCP, что даёт $O(m + \log n)$.
3. Или использовать технику «ускоренного бинарного поиска» с LCP: сравнивать не весь образец, а только часть после известного общего префикса.

Но в рамках данного вопроса достаточно знать базовый вариант $O(m \log n + k)$.

## 4. Массив LCP (дополнительно)

**LCP-массив**: $lcp[i]$ = длина наибольшего общего префикса суффиксов $S[sa[i]..]$ и $S[sa[i-1]..]$.

Строится за $O(n)$ по SA и обратному массиву рангов. Позволяет:
- Ускорить поиск подстроки до $O(m + \log n + k)$.
- Найти LCS двух строк: $\max(lcp[i])$ для пар из разных строк.
- Вычислить число различных подстрок: $n(n+1)/2 - \sum lcp[i]$.

## 5. Резюме для экзамена

| Аспект | Ответ |
| :--- | :--- |
| **Суффиксный массив** | Отсортированный массив индексов всех суффиксов строки |
| **Построение через ST** | In-order обход листьев суффиксного дерева. $O(n)$ |
| **Поиск подстроки** | Бинарный поиск по SA. $O(m \log n + k)$ |
| **Память** | $O(n)$ (значительно меньше, чем у суффиксного дерева) |
| **Преимущества перед ST** | Компактность, простота реализации, кэш-локальность |
| **Недостатки** | Поиск медленнее ($O(m \log n)$ vs $O(m)$), нужен LCP для сложных задач |
