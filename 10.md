# Вопрос 10. Trie. Основные операции. Compact Trie. Оценка алгоритмической сложности выполнения операций

---

## 1. Определение и идея

**Trie (префиксное дерево, бор)** — это древовидная структура данных для хранения множества строк (или других последовательностей), в которой:
- Каждый **узел** соответствует одному символу алфавита.
- Путь от корня до некоторого узла задаёт **префикс** одной или нескольких строк.
- Строки хранятся не явно в узлах, а как **пути** от корня к специальным терминальным (конечным) узлам.

> **Главное преимущество:** Время поиска строки зависит только от её длины $m$, но **не зависит** от общего количества строк $n$ в словаре. Это делает Trie идеальным для автодополнения, проверки орфографии, IP-маршрутизации и как базу для более сложных структур (суффиксные деревья, Ахо-Корасик).

### Структура узла (C++)

Для простоты будем считать алфавит строчными латинскими буквами (`a-z`). В реальных задачах часто используют `std::map` или `std::unordered_map` вместо фиксированного массива.

```cpp
#include <iostream>
#include <string>
#include <vector>

const int ALPHABET_SIZE = 26;

struct TrieNode {
    TrieNode* children[ALPHABET_SIZE]; // Указатели на потомков по символам
    bool isEndOfWord;                   // Флаг конца слова
    
    TrieNode() : isEndOfWord(false) {
        for (int i = 0; i < ALPHABET_SIZE; ++i)
            children[i] = nullptr;
    }
};
```

## 2. Основные операции

### 2.1. Вставка (Insert)

**Алгоритм:**
1. Начинаем с корня.
2. Для каждого символа строки:
   - Вычисляем индекс: `idx = c - 'a'`.
   - Если `children[idx] == nullptr`, создаём новый узел.
   - Переходим в `children[idx]`.
3. После обработки всех символов ставим флаг `isEndOfWord = true` в конечном узле.

**Код на C++:**

```cpp
void insert(TrieNode* root, const std::string& word) {
    TrieNode* curr = root;
    for (char c : word) {
        int idx = c - 'a';
        if (curr->children[idx] == nullptr) {
            curr->children[idx] = new TrieNode();
        }
        curr = curr->children[idx];
    }
    curr->isEndOfWord = true;
}
```

### 2.2. Поиск точного совпадения (Search)

**Алгоритм:**
1. Идём от корня по символам строки.
2. Если на каком-то шаге нужный потомок отсутствует (`nullptr`) — строки нет в словаре.
3. Если прошли всю строку, проверяем флаг `isEndOfWord`. Если `true` — слово найдено, иначе существует лишь префикс.

**Код на C++:**

```cpp
bool search(TrieNode* root, const std::string& word) {
    TrieNode* curr = root;
    for (char c : word) {
        int idx = c - 'a';
        if (curr->children[idx] == nullptr) return false;
        curr = curr->children[idx];
    }
    return curr->isEndOfWord;
}
```

### 2.3. Поиск по префиксу (StartsWith)

Проверяет, существует ли в словаре хотя бы одно слово с заданным префиксом.

```cpp
bool startsWith(TrieNode* root, const std::string& prefix) {
    TrieNode* curr = root;
    for (char c : prefix) {
        int idx = c - 'a';
        if (curr->children[idx] == nullptr) return false;
        curr = curr->children[idx];
    }
    return true; // Дошли до конца префикса — он существует
}
```

### 2.4. Удаление (Delete)

Удаление сложнее, так как нельзя просто удалить узлы — они могут быть частью других слов.

**Алгоритм (рекурсивный):**
1. Спускаемся до конца слова.
2. Если `isEndOfWord == false`, слова нет — ничего не делаем.
3. Снимаем флаг `isEndOfWord`.
4. При возврате из рекурсии: если у текущего узла **нет потомков** и он **не является концом другого слова**, удаляем его и возвращаем `nullptr` родителю. Иначе оставляем.

**Код на C++:**

```cpp
// Возвращает true, если текущий узел можно безопасно удалить
bool removeHelper(TrieNode* node, const std::string& word, int depth) {
    if (!node) return false;

    // Дошли до конца слова
    if (depth == (int)word.size()) {
        if (!node->isEndOfWord) return false; // Слова не было
        node->isEndOfWord = false;
        
        // Узел можно удалить, если у него нет детей
        for (int i = 0; i < ALPHABET_SIZE; ++i)
            if (node->children[i]) return false;
        return true; // Сигнал родителю: удали меня
    }

    int idx = word[depth] - 'a';
    if (!node->children[idx]) return false;

    bool shouldDeleteChild = removeHelper(node->children[idx], word, depth + 1);

    if (shouldDeleteChild) {
        delete node->children[idx];
        node->children[idx] = nullptr;
        
        // Текущий узел тоже можно удалить, если он не конец слова и пуст
        if (!node->isEndOfWord) {
            for (int i = 0; i < ALPHABET_SIZE; ++i)
                if (node->children[i]) return false;
            return true;
        }
    }
    return false;
}

void remove(TrieNode* root, const std::string& word) {
    removeHelper(root, word, 0);
}
```

## 3. Compact Trie (Сжатое префиксное дерево)

### Проблема обычного Trie
В обычном Trie длинные цепочки узлов с одним потомком занимают много памяти. Например, слова «banana», «bandana» будут иметь общую цепочку `b → a → n`, даже если нет других слов на «ba...».

### Решение: Compact Trie (Patricia / Radix Tree)
В сжатом дереве каждое ребро помечается не одним символом, а **целой подстрокой**. Узлы, имеющие ровно одного потомка и не являющиеся концом слова, **схлопываются** с этим потомком.

**Пример:**
Обычный Trie для {"banana", "band"}:
```
b → a → n → a → n → a*
             ↘ d*
```

Compact Trie:
```
root
 └── "ban" → "ana"*
          ↘ "d"*
```

### Особенности реализации
- Рёбра хранят подстроку (или пару `(start, length)` в исходной строке для экономии памяти).
- При поиске нужно сравнивать не один символ, а целую подстроку на ребре.
- При вставке может потребоваться **расщепление ребра**, если новый ключ расходится с существующим посередине метки ребра.

> **Compact Trie** занимает $O(n)$ памяти (где $n$ — суммарная длина всех строк), в то время как обычный Trie может занимать $O(n \cdot |\Sigma|)$ в худшем случае из-за пустых указателей.

## 4. Оценка алгоритмической сложности

Пусть:
- $m$ — длина обрабатываемой строки (для поиска/вставки одной строки),
- $N$ — суммарная длина всех строк в словаре,
- $|\Sigma|$ — размер алфавита,
- $n$ — количество строк в словаре.

### Обычный Trie

| Операция | Время | Память | Примечание |
| :--- | :--- | :--- | :--- |
| **Вставка** | $O(m)$ | $O(m)$ новых узлов (худший случай) | Не зависит от $n$ |
| **Поиск** | $O(m)$ | — | Не зависит от $n$ |
| **Поиск префикса** | $O(m)$ | — | Не зависит от $n$ |
| **Удаление** | $O(m)$ | — | Рекурсивный спуск + подъём |
| **Память (вся структура)** | $O(N \cdot |\Sigma|)$ | Массив детей в каждом узле | Можно уменьшить через map/hashmap |

> **Важно:** Сложность $O(m)$ означает, что поиск в Trie **быстрее**, чем бинарный поиск в отсортированном массиве строк ($O(m \log n)$), так как нет множителя $\log n$.

### Compact Trie

| Операция | Время | Память | Примечание |
| :--- | :--- | :--- | :--- |
| **Вставка** | $O(m)$ | $O(m)$ | Может потребоваться расщепление ребра |
| **Поиск** | $O(m)$ | — | Сравнение подстрок на рёбрах |
| **Память (вся структура)** | $O(N)$ | Линейна от суммарной длины | Значительно меньше обычного Trie |

### Почему поиск за $O(m)$?

При поиске мы обрабатываем **ровно один символ** строки на каждом уровне дерева (в обычном Trie) или сравниваем подстроку, суммарная длина всех сравнений по пути не превышает $m$ (в Compact Trie). Мы никогда не возвращаемся назад и не перебираем другие ветви. Следовательно, время строго пропорционально длине искомой строки. $\blacksquare$

## 5. Полный пример использования (C++)

```cpp
int main() {
    TrieNode* root = new TrieNode();

    // Вставка
    insert(root, "apple");
    insert(root, "app");
    insert(root, "banana");
    insert(root, "band");

    // Поиск
    std::cout << "search(apple): " << search(root, "apple") << "\n";   // 1
    std::cout << "search(app): " << search(root, "app") << "\n";       // 1
    std::cout << "search(ap): " << search(root, "ap") << "\n";         // 0
    std::cout << "startsWith(ap): " << startsWith(root, "ap") << "\n"; // 1

    // Удаление
    remove(root, "app");
    std::cout << "После удаления app:\n";
    std::cout << "search(app): " << search(root, "app") << "\n";       // 0
    std::cout << "search(apple): " << search(root, "apple") << "\n";   // 1

    return 0;
}
```

### Вывод:
```
search(apple): 1
search(app): 1
search(ap): 0
startsWith(ap): 1
После удаления app:
search(app): 0
search(apple): 1
```

## 6. Резюме для экзамена

1. **Trie** — префиксное дерево, где путь от корня кодирует строку. Поиск/вставка за $O(m)$, где $m$ — длина строки (не зависит от размера словаря).
2. **Основные операции:** вставка (спуск + создание узлов), поиск (спуск + проверка флага), поиск префикса (спуск без проверки флага), удаление (рекурсивный спуск с очисткой хвостов).
3. **Compact Trie** — сжатая версия, где рёбра помечены подстроками. Экономит память до $O(N)$ вместо $O(N \cdot |\Sigma|)$. Требует расщепления рёбер при вставке.
4. **Сложность:** Все основные операции — $O(m)$ по времени. Память обычного Trie — $O(N \cdot |\Sigma|)$, Compact Trie — $O(N)$.
5. **Применения:** автодополнение, проверка орфографии, IP-маршрутизация, основа для суффиксных деревьев и Ахо-Корасик.
