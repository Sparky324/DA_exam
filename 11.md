# Вопрос 11. PATRICIA Trie. Основные операции. Оценка алгоритмической сложности выполнения операций

---

## 1. Определение и отличие от обычного/Compact Trie

**PATRICIA** (Practical Algorithm To Retrieve Information Coded in Alphanumeric) — это специфическая реализация сжатого префиксного дерева (Compact Trie), предложенная Дональдом Моррисоном в 1968 году.

### Ключевые отличия от обычного Compact Trie:
1.  **Бинарность:** Классическая PATRICIA работает с **бинарным представлением** ключей (битовыми строками), а не с символами алфавита. Каждый узел имеет ровно двух потомков (0 и 1).
2.  **Индекс бита:** В каждом внутреннем узле хранится не подстрока, а **номер бита** (`bit_index`), по которому происходит ветвление. Это позволяет пропускать длинные совпадающие префиксы без их хранения.
3.  **Обратные ссылки (Back-links):** В отличие от обычного Trie, где листья указывают на данные, в PATRICIA листья могут указывать обратно на внутренние узлы. Это позволяет избежать создания лишних узлов для различения ключей, которые являются префиксами друг друга.
4.  **Отсутствие явного хранения строк:** Строки (ключи) хранятся отдельно или только в листьях. Внутренние узлы содержат только индекс проверяемого бита и указатели.

> **Главное преимущество:** Количество внутренних узлов в PATRICIA строго равно $N - 1$ (где $N$ — количество ключей), независимо от длины ключей. Это делает структуру чрезвычайно компактной по памяти.

## 2. Структура узла (C++)

```cpp
#include <iostream>
#include <string>
#include <cstdint>

// Для простоты работаем со строками как с последовательностями байтов/битов
// В реальной реализации часто используют uint32_t или std::bitset

struct PatriciaNode {
    int bit_index;      // Номер бита, по которому ветвимся (-1 для листа)
    PatriciaNode* left; // Бит = 0
    PatriciaNode* right;// Бит = 1
    
    // Данные хранятся только если этот узел является концом ключа
    // В классической PATRICIA данные могут быть и во внутренних узлах
    std::string key;    
    bool has_key;       

    PatriciaNode() : bit_index(-1), left(nullptr), right(nullptr), has_key(false) {}
};
```

### Вспомогательная функция: получение бита

```cpp
// Возвращает значение бита по индексу idx в строке key
// Если idx выходит за пределы строки, возвращаем 0 (или специальный маркер)
int getBit(const std::string& key, int idx) {
    int byte_idx = idx / 8;
    int bit_idx = 7 - (idx % 8); // Считаем от старшего бита к младшему
    
    if (byte_idx >= (int)key.size()) return 0;
    
    return (key[byte_idx] >> bit_idx) & 1;
}
```

## 3. Основные операции

### 3.1. Поиск (Search)

Поиск в PATRICIA уникален тем, что мы спускаемся по дереву, проверяя биты ключа согласно `bit_index` в узлах, пока не упрёмся в узел, чей `bit_index` **меньше или равен** текущему проверяемому биту (или пока не достигнем листа). Затем нужно **обязательно сравнить** найденный ключ с искомым полностью.

**Алгоритм:**
1. Начинаем с корня.
2. Пока `current->bit_index > prev_bit_index`:
   - Проверяем бит искомого ключа по индексу `current->bit_index`.
   - Идём влево (бит=0) или вправо (бит=1).
   - Запоминаем предыдущий `bit_index` для обнаружения цикла/листа.
3. Когда цикл остановился, мы нашли кандидата.
4. Сравниваем `candidate->key` с искомым ключом. Если равны — найдено, иначе нет.

```cpp
PatriciaNode* search(PatriciaNode* root, const std::string& key) {
    if (!root) return nullptr;
    
    PatriciaNode* curr = root;
    int prev_bit = -1;
    
    // Спускаемся, пока bit_index возрастает
    while (curr->bit_index > prev_bit) {
        prev_bit = curr->bit_index;
        if (getBit(key, curr->bit_index) == 0)
            curr = curr->left;
        else
            curr = curr->right;
    }
    
    // Проверка полного совпадения
    if (curr->has_key && curr->key == key) return curr;
    return nullptr;
}
```

> **Важно:** Без финального сравнения поиск может дать ложноположительный результат, так как дерево различает ключи только по первым различным битам.

### 3.2. Вставка (Insert)

Вставка сложнее поиска, так как нужно найти место расхождения нового ключа с существующими.

**Алгоритм:**
1. Выполняем поиск, чтобы найти ближайший существующий ключ-кандидат.
2. Если кандидат совпадает с новым ключом — ничего не делаем (или обновляем данные).
3. Находим **первый различающийся бит** между новым ключом и ключом-кандидатом. Пусть это бит `diff_bit`.
4. Снова спускаемся от корня, пока `node->bit_index < diff_bit`.
5. Создаём новый внутренний узел с `bit_index = diff_bit`.
6. Подцепляем новый узел в дерево:
   - Если бит `diff_bit` нового ключа = 0, то левый потомок нового узла ведёт к новому листу (или данным), а правый — к тому поддереву, которое было здесь раньше (и наоборот).
   - Родительский указатель перенаправляется на новый узел.

```cpp
// Вспомогательная: поиск первого различающегося бита
int findFirstDiffBit(const std::string& a, const std::string& b) {
    int max_len = std::max(a.size(), b.size()) * 8;
    for (int i = 0; i < max_len; ++i) {
        if (getBit(a, i) != getBit(b, i)) return i;
    }
    return -1; // Строки идентичны
}

void insert(PatriciaNode*& root, const std::string& key) {
    // 1. Поиск ближайшего соседа
    PatriciaNode* candidate = search(root, key); // Упрощённо: если null, нужен спец. поиск ближайшего
    // Для корректности предположим, что у нас есть функция findClosest, 
    // которая возвращает узел даже при неудачном поиске
    
    // Если корень пуст
    if (!root) {
        root = new PatriciaNode();
        root->key = key;
        root->has_key = true;
        root->bit_index = -1; // Лист
        return;
    }
    
    // Находим ближайший узел (даже если точного совпадения нет)
    PatriciaNode* curr = root;
    int prev_bit = -1;
    while (curr->bit_index > prev_bit) {
        prev_bit = curr->bit_index;
        if (getBit(key, curr->bit_index) == 0) curr = curr->left;
        else curr = curr->right;
    }
    
    // 2. Проверка на дубликат
    if (curr->has_key && curr->key == key) return;
    
    // 3. Находим бит расхождения
    int diff_bit = findFirstDiffBit(key, curr->key);
    if (diff_bit == -1) return; // Не должно случиться, если ключи разные
    
    // 4. Спускаемся снова, чтобы найти место для вставки нового внутреннего узла
    PatriciaNode* parent = nullptr;
    curr = root;
    prev_bit = -1;
    while (curr->bit_index > prev_bit && curr->bit_index < diff_bit) {
        parent = curr;
        prev_bit = curr->bit_index;
        if (getBit(key, curr->bit_index) == 0) curr = curr->left;
        else curr = curr->right;
    }
    
    // 5. Создаём новый узел
    PatriciaNode* newNode = new PatriciaNode();
    newNode->bit_index = diff_bit;
    newNode->key = key;
    newNode->has_key = true;
    
    // Определяем, куда цеплять старый curr и куда новые данные
    if (getBit(key, diff_bit) == 0) {
        newNode->left = newNode; // Сам на себя (лист) или отдельный узел данных
        newNode->right = curr;
    } else {
        newNode->left = curr;
        newNode->right = newNode;
    }
    
    // 6. Подцепляем к родителю
    if (!parent) {
        root = newNode;
    } else if (getBit(key, parent->bit_index) == 0) {
        parent->left = newNode;
    } else {
        parent->right = newNode;
    }
}
```

> **Примечание:** Реализация вставки в PATRICIA нетривиальна из-за необходимости обрабатывать обратные ссылки и случаи, когда новый ключ является префиксом существующего. Выше приведена упрощённая схема. В экзаменационном ответе достаточно описать алгоритм и понять идею «поиска места расхождения».

### 3.3. Удаление (Delete)

Удаление в PATRICIA выполняется редко, так как структура оптимизирована для статических или редко меняющихся наборов данных.
**Алгоритм:**
1. Найти удаляемый ключ.
2. Пометить узел как «не содержащий ключ» (`has_key = false`).
3. *(Опционально)* Если узел стал бесполезным (не содержит ключ и имеет только одного значимого потомка), можно попытаться схлопнуть его с родителем, но это сложно из-за обратных ссылок. Часто просто оставляют «мёртвые» узлы.

## 4. Оценка алгоритмической сложности

Пусть:
- $N$ — количество ключей в дереве.
- $W$ — максимальная длина ключа в битах (например, 32 для IPv4, 128 для IPv6, или $8 \cdot L$ для строк длины $L$).

| Операция | Время | Память | Примечание |
| :--- | :--- | :--- | :--- |
| **Поиск** | $O(W)$ | — | Спуск по высоте + одно сравнение ключей |
| **Вставка** | $O(W)$ | $O(1)$ новых узлов | Два спуска + создание одного внутреннего узла |
| **Удаление** | $O(W)$ | — | Поиск + пометка |
| **Память (вся структура)** | $O(N)$ | Строго $N-1$ внутренних узлов | Не зависит от длины ключей! |

### Почему поиск $O(W)$, а не $O(N)$?
Высота PATRICIA ограничена длиной ключа в битах $W$, так как `bit_index` строго возрастает на каждом уровне дерева. Мы никогда не проверяем один и тот же бит дважды. Следовательно, глубина спуска $\leq W$.
Финальное сравнение ключей занимает $O(W)$ (или $O(L)$ для строк).
Итого: $O(W)$.

### Сравнение с обычным Trie

| Характеристика | Обычный Trie | Compact Trie | PATRICIA |
| :--- | :--- | :--- | :--- |
| **Память** | $O(N \cdot W \cdot |\Sigma|)$ | $O(N \cdot W)$ | **$O(N)$** |
| **Поиск** | $O(W)$ | $O(W)$ | $O(W)$ |
| **Вставка** | $O(W)$ | $O(W)$ | $O(W)$ |
| **Зависимость от алфавита** | Да | Да | **Нет (бинарная)** |
| **Сложность реализации** | Низкая | Средняя | Высокая |

> **Для экзамена:** Главное достоинство PATRICIA — **линейная память $O(N)$** независимо от длины ключей, и гарантированное время поиска $O(W)$. Это делает её идеальной для маршрутизации (IP-таблицы), где ключи фиксированной длины, а их количество велико.

---

## 5. Резюме для экзамена

1.  **PATRICIA** — бинарное сжатое префиксное дерево, где ветвление происходит по номерам битов, а не по символам.
2.  **Структура:** Внутренние узлы хранят `bit_index` и два указателя. Листья/данные могут быть связаны обратными ссылками.
3.  **Поиск:** Спуск по возрастающим `bit_index` + обязательная полная проверка ключа в конце. Время $O(W)$.
4.  **Вставка:** Поиск ближайшего соседа → нахождение первого различающегося бита → повторный спуск до места вставки → создание одного нового внутреннего узла. Время $O(W)$.
5.  **Память:** Строго $O(N)$ внутренних узлов. Не зависит от длины ключей и размера алфавита.
6.  **Применение:** IP-маршрутизация, словари с длинными ключами, системы с фиксированной длиной ключа.
